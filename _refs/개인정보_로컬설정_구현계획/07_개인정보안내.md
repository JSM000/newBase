# 7. 페이지 내 개인정보 관리 중요성 안내

## 목적

`/settings` 페이지가 (계산기 업로드와 달리) **브라우저에 영구적으로 데이터를 남기는
첫 화면**이라는 점을 사용자가 명확히 인지하게 한다.

## 배치 위치 및 스타일

`upload-section.tsx`에 이미 있는 안내 박스 스타일(호박색 배경, 리스트형 안내)을 그대로
재사용해 일관성을 유지한다.

```tsx
<div className="rounded-lg border border-amber-200 bg-amber-50 p-4 text-sm">
  <p className="mb-1 font-semibold text-amber-800">개인정보 보관 안내</p>
  <ul className="list-inside list-disc space-y-1 text-amber-700">
    <li>이 페이지에 입력한 정보는 서버로 전송되지 않고, 이 기기의 브라우저에만 저장됩니다.</li>
    <li>저장된 정보는 {'{formattedExpiresAt}'} 이후 이 사이트에 다시 방문하면 자동으로
        삭제됩니다 — 그 전까지는 방문하지 않아도 브라우저에 그대로 남아 있습니다.</li>
    <li>확실하게 지우고 싶다면 사이트를 벗어나기 전에 아래 "전체 삭제"를 눌러주세요 —
        특히 공용 PC·공용 기기에서는 꼭 눌러주세요.</li>
    <li>거주지는 정확한 주소가 아니라 좌표로만 저장되며, 상세 주소는 저장하지 않습니다.</li>
  </ul>
</div>
```

`{formattedExpiresAt}` — [06_자동삭제.md](06_자동삭제.md)의 `getExpiresAt(savedAt)` 값을
사람이 읽을 수 있게 포맷한 문자열(예: "2026년 10월 9일 오후 3시 12분")로, 저장된 데이터가
있을 때만 표시한다. 아직 아무것도 저장 전이면 "저장 시점부터 20일이 지난 뒤 이 사이트에
다시 방문하면 자동으로 삭제됩니다"처럼 일반 안내 문구로 대체한다.

두 번째·세 번째 문구는 [06_자동삭제.md](06_자동삭제.md)에서 설명한 "방문해야만 지워진다"는
실제 동작 방식을 그대로 드러낸다 — "그 날짜에 자동으로 사라진다"고 오해하게 두지 않고,
확실히 지우려면 수동 삭제가 유일한 보장 수단이라는 걸 명시한다.

## 페이지 하단 — 전체 삭제 버튼

- 설정 페이지 맨 아래에 "저장된 내 정보 전체 삭제" 버튼 배치
- 클릭 시 확인 다이얼로그(기존 `@radix-ui/react-dialog` 사용 가능) → 확인 시
  `useUserSettingsStore`의 `reset()` 호출 + 삭제 완료 문구
