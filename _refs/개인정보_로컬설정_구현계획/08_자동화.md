# 8. 저장된 데이터가 있을 때 자동으로 결과 보여주기

## 요구사항

로컬에 저장된 정보가 있으면, 점수계산기(지역 선택 포함)·통계지도 모두 **사용자가 다시
선택해야 하는 과정을 생략**하고 바로 결과 화면으로 넘어간다.

## 8-1. 점수계산기(`/calculator`)

### 현재 흐름

`upload-section.tsx` → 파일 업로드 → `useParseExcel` → `calculateScore` → 결과 화면
(`use-score-store.ts`의 `step: 'upload' | 'result'`).

### 자동화 후 흐름

1. `ScoreCalculatorContainer` 마운트 시, `useUserSettingsStore`에 [05](05_엑셀파일.md)의
   `savedParsedFile`가 있고 아직 만료([06](06_자동삭제.md))되지 않았다면:
   - `useScoreStore.setParsed(savedParsedFile.data)`
   - 설정 스토어의 [04](04_학교급.md) `schoolLevel`이 유치원/초등학교면 `inputs.teacherType`으로 시딩
     (중·고등학교면 계산기가 아직 구현 안 된 학교급이라 시딩하지 않음 — 영구 제약 아님,
     추후 중고등 계산 로직 추가 시 여기도 확장 필요)
   - `calculateScore(...)` 실행 → `setResult(...)` → `setStep('result')`
   - **업로드 화면 자체를 건너뛴다** (사용자는 바로 결과 탭을 본다)
2. 저장된 데이터가 없거나 만료됐으면 기존과 동일하게 업로드 화면부터 시작한다.
3. 결과 화면에는 "저장된 이전 데이터로 불러왔습니다 · 새 파일 업로드" 같은 표시/버튼을 두어,
   사용자가 원하면 언제든 새로 업로드해 갱신할 수 있게 한다(자동화가 "새 파일 업로드"
   경로를 막아서는 안 됨).

### 주의

가산점 직접 입력 항목(`schoolZone`, `preferentialBonus`, `headTeacherSchoolZone`,
`specialRoleType`, `sportsAwards` 등 — [01](01_근무지역.md)에서 확인했듯 이번 로컬 설정
범위 밖)은 계속 매번 기본값(0/해당없음)에서 시작한다. 자동화는 "파일 재업로드 생략"과
"학교급 시딩"까지만 다루고, 가산점 수동 입력까지 대신 채워주지는 않는다.

## 8-2. 통계지도(`/statistics`)

### 현재 흐름

`SchoolFilterBar`에서 학교급(`level`)·시군(`sigungu`) 선택 → 지도에 필터링된 학교 표시.
"집에서 학교까지" 패널(`CommutePanel`)을 열어 주소 검색 → 후보 선택 → 소요시간 순위 조회.

### 자동화 후 흐름

`StatisticsContainer` 마운트 시 `useUserSettingsStore` 값으로 아래를 시딩:

1. **시·군 필터** — 관외전보 고려 중([02](02_전보유형.md))이고 `desiredSigungu`가
   있으면 그 값을, 아니면 `currentSigungu`([01](01_근무지역.md))를 `sigungu` state
   초기값으로 설정한다(`resolveTargetSigungu` 헬퍼). 관외 희망 지역이 있는데 "떠나려는
   지역" 통계를 기본으로 보여주는 건 실익이 적어서, 있으면 희망 지역을 우선한다.
2. **학교급 필터** — [04](04_학교급.md)의 `schoolLevel`을 `resolveTargetLevel`로
   `SchoolLevelFilter`(초/중/고/전체)에 매칭해 `level` 초기값으로 설정 (유치원은 통계
   페이지 대상 학교급이 아니라 매칭 없음 → `'all'` 유지).

**집 위치 자동 길찾기는 구현했다가 제거했다** — 지도에 들어가자마자 패널이 자동으로
열리고 길찾기까지 알아서 실행되는 게 사용자 입장에서 원치 않는 동작이라는 피드백을
받았다. 그래서 `CommutePanel`의 `savedHomeCoords` prop과 관련 자동 실행 로직을
전부 제거했고, `homeCoords`는 이제 이 자동화 흐름에서 쓰이지 않는다(주소 검색 UI는
여전히 [03](03_거주주소.md)에서 설명한 대로 설정 페이지에 남아있다 — 단지 통계지도
쪽에서 그 좌표를 자동으로 소비하지 않을 뿐).

시·군/학교급 필터 자동 채움(위 1·2)은 유지한다 — 이건 진입 즉시 눈에 보이는 필터
드롭다운 값이 바뀌는 정도라 자동 길찾기 실행만큼 거슬리지 않는다는 판단.

## 8-3. 계산기 지역 선택(`/calculator`)

### 현재 흐름

`/calculator`(`region-select-container.tsx`)는 충북 지도에서 시·군을 클릭 → 관내/관외
모달 → 이 앱은 현재 **청주시·관외** 조합만 지원해서, 그 조합일 때만 "점수 계산 시작"
버튼으로 `/calculator/score`로 이동할 수 있다.

### 자동화 후 흐름

`RegionSelectContainer` 마운트 시 저장된 `currentSigungu`·`transferPreference`
([01](01_근무지역.md), [02](02_전보유형.md))이 지원 조합(청주시 + 관외)과 일치하면,
지도·모달 선택 과정 없이 곧바로 `router.replace('/calculator/score')`로 이동한다.
그 뒤 이어지는 자동 로드([8-1](08_자동화.md#8-1-점수계산기calculator))가 이어받아,
저장된 엑셀 데이터까지 있으면 결과 화면까지 한 번에 도달한다 — 홈 화면에서 "전보 점수
계산"을 눌렀을 때 지도 클릭·모달·업로드 없이 바로 계산 결과가 보이는 게 최종 목표.

저장된 정보가 지원 조합이 아니거나(관내/미정, 청주시 외 지역) 아직 없으면 기존처럼
지도에서 직접 고른다.

## 연동 지점 정리

- `src/containers/score-calculator/score-calculator-container.tsx` — 마운트 시 저장된
  `ParsedFile` 유무 체크 후 바로 결과로 분기하는 로직 추가
- `src/store/use-score-store.ts` — 초기 `step`/`inputs`를 설정 스토어 기반으로 계산하는
  헬퍼 추가
- `src/containers/statistics/statistics-container.tsx` — `sigungu`/`level` 초기값 계산만
  유지 (자동 길찾기 실행은 제거됨)
- `src/containers/score-calculator/region-select-container.tsx` — 마운트 시 지원 조합
  체크 후 `/calculator/score`로 리다이렉트
