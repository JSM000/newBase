# 학교 별점·조회수 기능 구현 계획

> 목표: `/statistics` 지도에서 학교별로 사용자가 **별점(1~5)**을 남기고, 학교 상세를 열면 **조회수**가 누적되어, 다른 사용자가 그 집계를 참고할 수 있게 한다.
> 성격: **흥미 중심** 기능 — 데이터 정확도·엄밀한 중복 차단은 목표가 아니다. "이동할 학교로서의 추천도"를 가볍게 모아 보여주는 용도.
> 관련 문서: `_refs/학교통계_지도_구현계획.md` (지도·상세 패널·순위 목록 기반 기능)

---

## 1. 범위

**포함 (v1)**

- 학교 상세 패널(`school-detail-panel.tsx`)에 별점 위젯 + 조회수 표시
- 별점: 1~5 정수, **브라우저(localStorage `client_id`)당 학교별 1표**, 재투표는 갱신
- 평균 별점 + **참여자 수** 표시 (예: `★ 4.2 (12명)`)
- 조회수: 상세 패널이 열릴 때 +1, **세션당 학교별 1회**(sessionStorage로 중복 제거)
- 순위 패널(`school-ranking-panel.tsx`)에 "별점순 / 조회수순" 정렬 기준 추가

**제외 (→ 9. 추후 과제)**

- 별점을 지도 마커 색상(표시 지표 드롭다운·범례·bucket)에 반영
- Supabase 익명 로그인(Anonymous Auth) 도입 — v1은 localStorage `client_id`로만 식별
- 텍스트 후기/코멘트, 신고·모더레이션, 정식 회원 계정
- 조회수 스팸 방지(서버 레이트리밋)

## 3. 아키텍처

### 3-1. 저장소: Supabase (무료 티어, Seoul 리전)

| 항목 | 선택 | 이유 |
|---|---|---|
| DB | Supabase Postgres | 자동 REST/JS 클라이언트. 쓰기는 브라우저 → Supabase 직접(아래 3-4), Vercel 함수 안 씀 |
| 인증 | **없음 (v1)** | 흥미 중심이라 localStorage `client_id`로 충분. 진짜 익명 로그인은 추후 |
| 무료 한도 | DB 500MB / 대역폭 5GB | 524개교·월 수천 세션 대비 1% 미만 |

**env** (`.env.local`에 커밋하지 않음 — 5번 결정):

```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_KEY
```

- 로컬: `NEXT_PUBLIC_SUPABASE_URL=... NEXT_PUBLIC_SUPABASE_KEY=... npm run dev` 로 실행
- 배포(Vercel): 프로젝트 환경변수로 등록
- KEY = 브라우저 노출용 공개 키. 대시보드의 `publishable`(`sb_publishable_...`) 또는 구형 프로젝트의 `anon`(`eyJ...`) — 둘 다 RLS 적용. `secret`/`service_role` 키는 사용하지 않음
- `src/lib/supabase.ts`에서 두 env가 없으면 소셜 기능 전체를 조용히 비활성화(별점 위젯·조회수 숨김) — 키 없이도 기존 지도는 정상 동작

### 3-2. 스키마 (`supabase/migrations/0001_school_social.sql`)

전문은 파일 참고. 권한 설계 핵심:

- `school_ratings` (client_id 포함) — **anon 직접 접근 전면 차단** (정책 없음 + `revoke`).
  읽기는 아래 집계 뷰로만, 쓰기는 `rate_school()` RPC(SECURITY DEFINER)로만.
- `school_rating_stats` — `security_invoker` **미지정**(뷰 소유자 postgres 권한 실행)이라
  anon은 집계 결과만 보고 원본 행엔 못 들어감. `grant select ... to anon` 명시.
- `school_views` — 카운터 하나뿐이라 공개. RLS `using(true)` 정책 + `grant select to anon`.
  쓰기는 `bump_school_view()` RPC로만.
- **`GRANT`를 반드시 명시**한다 — Supabase는 SQL Editor로 만든 뷰/테이블에 anon 권한을
  자동 부여하지 않는 경우가 있어(`42501 permission denied for view`), RLS 정책만으론
  부족하고 `grant select`가 따로 필요하다.
- 파일은 재실행해도 안전(idempotent): `create table if not exists`,
  `create or replace function`, `drop ... if exists` 조합.

- 개별 별점 행에 `insert/update/delete` 정책을 안 두고 `rate_school` RPC(`security definer`)로만 쓰게 해서, "남의 별점 행을 마음대로 수정"하는 경로를 원천 차단
- `rating` 값 검증은 테이블 `check`와 RPC 인자 타입(`smallint`)에서 이중으로

### 3-3. 읽기 경로 — 라우트 핸들러 + CDN 캐시

`src/app/api/school-social/route.ts` (GET):

- Supabase(anon)로 `school_rating_stats` + `school_views` 조회 → 학교코드 기준 병합
- 반환 형태: `{ [schulCode]: { avg: number | null, count: number, views: number } }`
- 응답 헤더:

  ```
  Cache-Control: public, s-maxage=60, stale-while-revalidate=300
  ```

- 동작(중요 — 크론 아님, lazy):
  - **요청이 들어왔을 때만** 캐시 나이를 보고 60초 지났으면 그때 1회 갱신
  - 이용자 없는 시간대 = 요청 없음 = **DB 조회 0회**
  - 별점 등록 후 남의 화면 반영까지 최대 ~60초 (흥미 중심이라 무해)
  - `stale-while-revalidate`: 60초 지난 뒤 첫 요청은 옛 값을 즉시 주고 백그라운드로 1회 갱신 → 사용자 체감 지연 없음
- ⚠️ Next 16의 라우트 핸들러 캐싱 시맨틱은 `node_modules/next/dist/docs/` 확인 후 확정(AGENTS.md 규칙). `Cache-Control` 헤더만으로 Vercel CDN 캐시가 안 걸리면 `unstable_cache(fn, ['school-social'], { revalidate: 60 })`로 대체
- 이 라우트는 **읽기 전용**이며 env(`NEXT_PUBLIC_SUPABASE_*`)를 서버에서도 그대로 사용

`src/hooks/use-school-social.ts`:

- `useSchoolSocial()` — 위 라우트를 `useQuery` (`staleTime: 60_000`, `queryKey: ['school-social']`)
- `useRateSchool()` — `supabase.rpc('rate_school', ...)` mutation + **낙관적 업데이트**(내 별점·평균·참여자 수를 즉시 반영), 성공/실패와 무관하게 localStorage에 내 별점 기록
- `useBumpView()` — `supabase.rpc('bump_school_view', ...)` fire-and-forget. 실패 시 콘솔 경고만

### 3-4. 쓰기 경로 — 브라우저 → Supabase 직접

- **별점**: 별 클릭 → `rate_school(client_id, schulCode, rating)` RPC. 낙관적으로 화면 먼저 갱신. 남들 화면엔 다음 캐시 갱신(≤60초) 때 반영
- **조회수**: 상세 패널 mount 시, `sessionStorage`의 "이번 세션에 본 학교" 집합에 `schulCode`가 없으면 `bump_school_view` 호출 후 집합에 추가. 실패해도 조용히 무시

### 3-5. 사용자 식별 — localStorage `client_id`

- 최초 진입 시 `crypto.randomUUID()`로 `client_id` 생성해 `localStorage['school-social:client-id']`에 저장, 이후 재사용
- 내가 남긴 별점은 `localStorage['school-social:my-ratings']`에 `{ [schulCode]: rating }`으로 보관 → 위젯이 "내 별점"을 표시할 때 서버 왕복 없이 여기서 읽음
- 한계(감수): localStorage 삭제·다른 브라우저·시크릿창 → 새 `client_id` = 재투표 가능. 흥미 중심 기능이라 허용

## 6. 순위 패널 연동

`statistics-container.tsx` / `school-ranking-panel.tsx`:

- 순위 기준에 **"별점순", "조회수순"** 2개를 기존 "표시 지표" 기준과 별개 축으로 추가

## 8. 네트워크·비용 예상 (월 2,000 세션 가정)

| 항목 | 세션당 | 월 총계 |
|---|---|---|
| 집계 fetch (`/api/school-social`, ~12KB gzip) | 1회 (브라우저 캐시로 세션 내 중복 제거) | ~2,000회 / **실제 DB 히트 ≈ 트래픽 비례, 시간당 몇 회** |
| 조회수 RPC (~300B) | ~10회 | ~20,000 write |
| 별점 RPC (~400B) | ~0.1회 | ~200 write |
| 아웃바운드 대역폭 | ~15KB | **~30MB/월** |

- CDN 캐시는 lazy 방식이라 이용자 없는 시간대엔 DB 조회 0. 트래픽이 적으면 캐시 히트율은 낮지만 그만큼 절대량도 적어 부담 없음
- Supabase 무료 한도 대비 1% 미만
- 저장량: `school_views` 524행 고정, `school_ratings`는 (참여 브라우저 수 × 관심 학교 수) — 수만 행이어도 수 MB

## 9. 추후 과제

1. **별점 → 지도 마커 색상**: `Indicator`를 `(School, social?) => number | null`로 확장, 범례/bucket 경계값 별점용 정의(1~5 고정 구간)
2. **Supabase 익명 로그인**: `client_id` → `auth.uid()` 마이그레이션. RLS를 `auth.uid() = user_id` 기반으로 강화, 안 쓰는 익명 계정 정리 SQL
3. **조회수 스팸 방지**: `bump_school_view` RPC에 `(client_id, school_code, 시각)` 로그 + 짧은 쿨다운, 또는 Edge 미들웨어 레이트리밋
4. **캐시 무효화 정교화**: `unstable_cache` + `revalidateTag('school-social')`를 쓰기 성공 시 호출해 "변경 시에만" 갱신 (지금은 시간 기반 60초로 충분)
5. 텍스트 후기, 신고/모더레이션
