# 개인정보 검출 기능 구현계획 (2026-10-02)

댓글 작성과 인사기록카드 업로드 두 곳에 개인정보 검출을 넣는 계획이다. **2026-10-02 구현 완료** — 결정 사항은 [05](05_결정필요.md), 구현 결과는 [04](04_작업단계.md) 4-0.

## 두 곳은 목적이 다르다

| | 댓글 | 인사기록카드 업로드 |
|---|---|---|
| 데이터가 가는 곳 | **서버에 저장되고 누구나 읽음** | 브라우저 안에서만 처리(서버 전송 없음 — 기존 불변조건) |
| 검출 목적 | 남의 개인정보가 **공개 게시**되는 걸 막기 | ① 점수 계산에 필요 없는 개인정보를 **보관하지 않기**(최소 처리) ② 사용자에게 "무엇이 들어 있고 어떻게 처리되는지" **알리기** ③ 인사기록카드가 아닌 파일(학생 명단 등)을 잘못 올렸을 때 **처리 중단** |
| 검출되면 | 차단 또는 경고 후 수정 유도 | 인사기록카드가 아닌 파일이면 처리 중단(가리기는 하지 않기로 함 — [05](05_결정필요.md) 5번) |
| 서버 검사 | **필요**(브라우저 검사는 우회 가능) | 불필요(서버로 안 감) |

## 공통 원칙

- 검출 규칙은 **한 파일**(`src/lib/pii-detect.ts`)에 모아 댓글·인사기록이 같이 쓴다. 댓글의 서버 검사는 같은 규칙을 SQL로 옮긴다.
- 검출은 **브라우저 안에서만** 돈다. 검출 결과(어떤 개인정보가 있었는지)도 서버로 보내지 않는다.
- 결과에는 **값을 담지 않는다** — "전화번호 1건"처럼 종류와 개수만. 화면·로그에 원문이 다시 찍히지 않게.
- 자동 검출은 완벽할 수 없다. 특히 사람 이름은 오검출·미검출이 둘 다 생긴다 → 댓글은 **신고 기능**으로 보완한다.
