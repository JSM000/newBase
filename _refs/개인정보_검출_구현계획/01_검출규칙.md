# 1. 검출 규칙 (`src/lib/pii-detect.ts`)

## 1-1. 검출 대상과 방식

| 종류 | 예 | 방식 | 강도(댓글) |
|---|---|---|---|
| 주민등록번호·외국인등록번호 | 900101-1234567, 9001011234567, 900101-1****** | 6자리(생년월일 유효성) + 구분자 + 7번째 자리 1~8 | 🔴 차단 |
| 휴대전화 | 010-1234-5678, 01012345678, 010 1234 5678 | 010·011·016~019 + 3~4자리 + 4자리 | 🔴 차단 |
| 일반전화 | 043-123-4567, 02-123-4567 | 지역번호(02, 031~064) + 3~4 + 4자리 | 🔴 차단 |
| 이메일 | abc@school.go.kr | 표준 이메일 형식 | 🔴 차단 |
| 계좌번호 | 국민 123456-01-123456 | 은행명 키워드 근처의 10~14자리 숫자(하이픈 포함) | 🔴 차단 |
| 상세 주소 | ○○로 12번길 34, 101동 1203호 | 도로명(로·길)+건물번호, 또는 "동·호" 조합 | 🟠 경고 |
| 실명 추정 + 직함 | 김철수 선생님, 이영희 교감, 박부장님 | 한글 2~4자 + 직함 접미어(선생님·쌤·교장·교감·부장·주무관·실장 등), 첫 글자가 흔한 성씨 | 🟠 경고 |
| 학교 내 특정인 지칭 | "교감 선생님이", "행정실장" | 직위 단독 언급 — 댓글이 **학교별**이라 직위만으로도 사람이 특정됨 | 🟡 안내(선택, [05](05_결정필요.md)) |

- 주민번호는 뒷자리를 일부 가린 형태(`-1******`)도 잡는다. 앞 6자리는 월(01~12)·일(01~31) 범위를 확인해 "학생 수 600123명" 같은 숫자를 덜 잡게 한다.
- 이름은 형식만으로 확실히 알 수 없어 **차단하지 않고 경고**로 둔다(성씨 목록 상위 100개 + 직함 접미어 조합일 때만).

## 1-2. 오검출 줄이기

통계지도 댓글엔 숫자가 많이 나온다(학급 수, 학생 수, 연도, 시간). 다음은 **잡지 않아야** 한다:

- `2026년 3월`, `24학급`, `학생 612명`, `주 20시간`, `1시간 10분`
- 연수·공문 번호 형식: `단재교-초-직무-2007-682`, `교육과정-1234`
- 학교 코드 `S110000924`(영문+숫자)

방법: 숫자 앞뒤 단위어(년·월·학급·명·시간·분·개)가 붙어 있으면 제외, 전화·주민번호는 자릿수와 구분자 패턴이 정확히 맞을 때만. 위 예시들을 테스트 케이스로 고정한다([04](04_작업단계.md)).

## 1-3. 결과 형식

```ts
type PiiKind = 'rrn' | 'mobile' | 'phone' | 'email' | 'account' | 'address' | 'personName' | 'roleMention';

interface PiiMatch {
  kind: PiiKind;
  severity: 'block' | 'warn' | 'info';
  start: number;   // 원문에서의 위치 — 화면 강조·가리기에만 쓰고 저장하지 않음
  end: number;
}

detectPii(text: string): PiiMatch[]
maskPii(text: string, matches?: PiiMatch[]): string   // 해당 구간을 '●●●'로 바꿈
summarizePii(matches: PiiMatch[]): Partial<Record<PiiKind, number>>  // 종류별 개수만
```

- 위치(start/end)는 화면에서 강조하거나 가릴 때만 쓰고, 어디에도 저장하거나 보내지 않는다.
- 요약(`summarizePii`)은 값 없이 종류와 개수만 담는다 → 안내 문구·로그에 써도 안전.

## 1-4. 서버(SQL) 쪽 규칙

댓글은 브라우저 검사를 우회해 RPC를 직접 부를 수 있으므로, **차단(🔴) 등급만** 같은 정규식으로 `add_school_comment` 안에서 한 번 더 검사한다(`_contains_blocked_pii(text) returns boolean`). 경고 등급(이름·주소)은 오검출 시 정상 댓글을 막게 되므로 서버에선 검사하지 않는다.

TS와 SQL 정규식이 어긋나지 않게, 테스트 케이스 목록 하나로 둘 다 검증한다([04](04_작업단계.md) 4-3).
