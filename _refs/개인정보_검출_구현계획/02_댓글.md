# 2. 댓글

대상 코드: `src/containers/statistics/school-comments.tsx`(입력 폼 `SchoolCommentForm`), `src/hooks/use-school-comments.ts`,
`supabase/migrations/0005_school_comments.sql`의 `add_school_comment`.

## 2-1. 작성 화면 — 입력하면서 바로 안내

- 본문을 입력할 때(300ms 디바운스) `detectPii`를 돌려 입력칸 아래에 안내를 띄운다.
  - 🔴 차단: "전화번호로 보이는 내용이 있어 등록할 수 없습니다." + **[가리고 등록]** 버튼(해당 부분을 `●●●`로 바꿔 입력칸에 반영)
  - 🟠 경고: "특정인을 알아볼 수 있는 이름이 있을 수 있어요. 그대로 등록할까요?" — 등록 버튼을 누르면 한 번 더 확인
- 차단 항목이 남아 있으면 등록 버튼 비활성.
- (구현 안 함) 입력칸 안 강조 표시 — 종류 안내 + [가리기] 버튼으로 대신했다.
- 안내 문구는 값을 다시 보여 주지 않고 종류만 말한다.

## 2-2. 닉네임 검사

닉네임 칸에 실명을 쓰는 경우가 많다. 닉네임도 같은 규칙으로 검사해:
- 전화·이메일 등 🔴 → 차단
- 이름 형식(한글 2~4자, 흔한 성씨로 시작) → "실명 대신 별명을 권장해요" 안내만(차단하지 않음 — "익명고양이" 같은 별명 오검출이 많음)

## 2-3. 서버 차단 (마이그레이션 0006)

- `_contains_blocked_pii(text)` 함수 추가 — 주민번호·전화·이메일·계좌 정규식([01](01_검출규칙.md) 1-4).
- `add_school_comment`에서 본문·닉네임 검사 → 걸리면 `raise exception 'contains_pii'`.
- 클라이언트 `commentErrorMessage`에 `contains_pii` → "개인정보(전화번호 등)가 포함되어 등록할 수 없습니다." 추가.
- 0005와 같이 재실행 안전하게 작성(함수만 `create or replace`/drop-create).

## 2-4. 이미 올라온 댓글 점검

배포 전에 쓰인 댓글이 있을 수 있으므로, 0006 실행 후 한 번 돌릴 점검 쿼리를 함께 둔다:

```sql
select id, school_code, created_at
from public.school_comments
where deleted_at is null
  and (public._contains_blocked_pii(body) or public._contains_blocked_pii(nickname));
```

결과는 id만 보고 대시보드에서 숨김 처리(`deleted_at`). 원문을 조회 결과에 찍지 않는다.

## 2-5. 신고 기능 (보완 장치)

자동 검출로 못 잡는 것(이름, 우회 표기 "공일공-일이삼사…")을 위해:
- 댓글마다 **[신고]** 버튼 → 사유 선택(개인정보 / 비방 / 기타).
- `report_school_comment(p_comment_id, p_client_id, p_reason)` RPC, 같은 client_id는 댓글당 1회.
- 서로 다른 신고자(IP 해시, 없으면 client_id 기준) **5명 이상**이면 자동으로 숨김(`deleted_at` + `hidden_reason='reports'`), 관리자는 대시보드에서 복구 가능. 신고는 브라우저당 하루 20건까지.
- 신고 테이블도 원본 접근 차단(RLS + revoke), 0005와 같은 원칙.

## 2-6. 안내 문구

입력 폼 하단 문구를 구체적으로:
"이름·전화번호·주소 등 다른 사람을 알아볼 수 있는 정보는 쓰지 마세요. 개인정보가 포함된 댓글은 등록되지 않거나 신고로 숨겨질 수 있습니다."
