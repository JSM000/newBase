# 1. 출발지/도착지 팝업 UI 구조

## 요청 내용

"출발지 입력, 도착지 입력을 누르면 팝업이 떠서 팝업에서 출발지와 도착지를 고르도록
구성하자. 출발지는 이전처럼 주소를 검색하고 5개의 결과 중에서 선택하면 출발지 입력창에
주소지가 입력되고, 도착지는 필터 선택을 팝업에서 선택하면 도착지에 결과가 텍스트로
정리되서 나오도록. 둘 다 입력되어 있는 상태에서 출퇴근 시간 계산 버튼을 누르면 사이드바에
기존의 결과 창이 나오도록." (다시입력 버튼은 불필요 — 참고 이미지의 지도 길찾기 UI에서
그 버튼만 빼고 구성)

## 필터 바: 박스 2줄 + 버튼 하나로 축소

`school-filter-bar.tsx`의 출퇴근 탭 영역을 `w-72` 박스(출발지/도착지 두 줄, 가운데 구분선)
+ "출퇴근 시간 계산" 버튼만 남도록 줄였다. 값이 없으면 회색 플레이스홀더("출발지 입력"/
"도착지 입력"), 있으면 실제 텍스트를 보여준다.

```tsx
<div className="w-72 max-w-full overflow-hidden rounded-lg border border-zinc-200">
  <button onClick={() => setOriginDialogOpen(true)}>
    {originLabel ?? '출발지 입력'}
  </button>
  <div className="border-t border-zinc-100" />
  <button onClick={() => setDestinationDialogOpen(true)}>
    {destinationSummary ?? '도착지 입력'}
  </button>
</div>
<button onClick={handleConfirmSearch} disabled={isRanking}>
  {isRanking ? '계산 중…' : '출퇴근 시간 계산'}
</button>
```

`originDialogOpen`/`destinationDialogOpen`은 `SchoolFilterBar` 로컬 state(`useState`) —
다른 컴포넌트가 알 필요 없는 순수 UI 상태라 훅이나 컨테이너로 끌어올리지 않았다.

## 출발지 팝업 — 기존 후보 선택 UI를 사이드바에서 그대로 옮김

`@/components/ui/dialog`(Radix 기반, 기존 `excel-data-dialog.tsx`가 쓰던 것과 동일)를
써서 `Dialog` 안에 주소 입력 + 검색 버튼 + 후보 목록을 넣었다. 후보 목록 렌더링·스타일은
이전에 `commute-panel.tsx`(사이드바)에 있던 것을 그대로 옮겨왔다 — 후보를 클릭하면
`onPickCandidate(c)` 호출 후 `setOriginDialogOpen(false)`로 팝업을 닫는다.

"저장된 집 위치 사용" 버튼도 이 팝업 안으로 들어왔다(있을 때만, `onUseSavedHome` prop).

## 도착지 팝업 — 전역 필터를 그대로 편집(임시 버퍼 없음)

설립구분/학교급/시·군은 순위 보기 탭·지도 전체와 공유하는 전역 필터라서, 팝업이 별도로
"임시 선택값"을 들고 있다가 확정할 때만 반영하는 방식이 아니라, 팝업 안 select도 바로
그 전역 state에 바인딩돼 있다(`SchoolScopeFields` 재사용). "확인" 버튼은 그냥 팝업을
닫기만 한다 — 선택은 이미 실시간으로 반영돼 있음.

```
const destinationSummary = destinationReady
  ? `${sigungu} · ${schulKndLabel(level)}${ownership === 'all' ? '' : ` · ${ownership}`}`
  : null;
```

`destinationReady`(= 이전 `addressReady`를 이름만 바꿈, `level !== 'all' && sigungu !== 'all'`)가
false인 동안은 도착지 박스가 계속 플레이스홀더로 남는다.

## `use-commute-search.ts`: 검색(①) / 확정(②) / 실행(③) 3단계로 재구성

기존엔 후보를 고르는 순간(`pickCandidate`) 바로 길찾기(`runRanking`)까지 실행됐는데, 이제
출발지·도착지를 순서 상관없이 각각 골라두고 마지막에 버튼 하나로 실행해야 하므로 단계를
분리했다:

- `searchAddress` — 주소 → 후보 목록만 조회. **`ready`(도착지 준비 여부) 게이트를 제거** —
  출발지 팝업은 도착지가 아직 안 정해졌어도 항상 열고 검색할 수 있어야 하기 때문
  (이전엔 "시·군과 학교급을 먼저 선택해주세요" alert로 막았던 부분).
- `pickCandidate` / `useSavedOrigin` — 출발지를 **확정만** 한다(길찾기 실행 없음).
- `confirmSearch`(신규) — 출발지(`pickedOrigin`)와 도착지(`ready`)가 둘 다 있어야 실행,
  "출퇴근 시간 계산" 버튼이 이걸 호출한다.

```ts
function confirmSearch() {
  if (!pickedOrigin || !ready || ranking.isPending) return;
  onResult(null);
  onSelectCode(null);
  runRanking(pickedOrigin, 0);
}
```

필터 바의 `handleConfirmSearch`가 버튼을 누른 시점에 `originLabel`/`destinationReady`를
먼저 확인해서 없는 쪽을 alert로 알려준 뒤에만 `onConfirmSearch`(컨테이너: `confirmSearch()` +
`setPanelMode('commute')`)를 호출한다 — 사이드바는 이 시점에만 열린다(팝업에서 고르는
동안엔 안 열림).

## `commute-panel.tsx`: 후보 선택 UI 제거

`candidates`/`onPickCandidate` props와 관련 렌더링을 통째로 뺐다. 이제 이 컴포넌트는
순수하게 "실행된 검색의 결과"만 보여준다 — 출발지 안내 한 줄(`pickedOrigin`, 읽기 전용),
에러 메시지(길찾기 에러만 — 지오코딩 에러는 이제 출발지 팝업에서 바로 보여줌), 스피너,
정렬·순위 목록, "나머지도 계산" 버튼.
