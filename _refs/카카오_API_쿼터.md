# 카카오 API 무료 쿼터 정리

> 집→학교 소요시간 기능(`_refs/학교_소요시간_순위_구현계획.md`)이 쓰는 카카오 API들의 무료
> 한도·과금 정리. 공식 문서 + 카카오 디벨로퍼스 콘솔 [쿼터] 탭 실측(2026-09-16) 기준.
> 이 기능이 아닌 다른 카카오 API를 새로 쓰게 되면 이 문서에 이어서 정리하면 됨.

---

## 1. 카카오모빌리티 길찾기 요금

| API | 무료 (일) | 초과 단가 | 목적지 | 승인 |
|---|---|---|---|---|
| **자동차 길찾기 (1:1)** | **10,000건** | 월 100만건까지 **8원/건** | 1 (경유지 ≤5) | 셀프서비스 |
| 다중 경유지 길찾기 | 5,000건 | — | 경유지 ≤30 | 셀프서비스 |
| 다중 목적지 길찾기 (1→N) | 1,000건 | 월 30만건까지 20원/건 | ≤30 | **제휴 신청 필요** |

- 출처: [developers.kakaomobility.com/price](https://developers.kakaomobility.com/price/), [길찾기 API](https://developers.kakaomobility.com/product/naviapi.html)
- **과금은 호출 건수 기준** — 응답 용량과 무관. `summary=true`로 경로를 빼도 1호출=1건 그대로 차감됨
- 다중 목적지 API는 무료량이 1/10이고 "요청당 1건 vs 목적지 수만큼" 카운트 방식이 공식 문서에 없음 → 이 프로젝트는 미사용
- QPS 제한 미공개(경험상 ~10/s)

## 2. 카카오 주소검색 (지오코딩)

- `GET https://dapi.kakao.com/v2/local/search/address.json` (REST 키, 서버). 조회당 1회, 실패
  시에만 `search/keyword.json` 폴백 (둘 다 항상 부르면 호출 2배라 안 함)
- 무료 쿼터는 아래 3번 표 참고

## 3. 카카오 디벨로퍼스 통합 쿼터 (2026-09-16, 콘솔 [쿼터] 탭 실측 확인)

### 3-1. 일간 쿼터 — 이 프로젝트가 쓰는 것만

| API | 무료(일) | 초과 단가 |
|---|---|---|
| 자동차 길찾기(`/v1/api/navi/directions`, 카카오내비) | 10,000건 | (1번 참고, 모빌리티 자체 가격표: 월 100만까지 8원/건) |
| 주소로 좌표 변환(`/local-open/.../search/address`, 카카오맵) | 100,000건 | 0.5원/건 |
| 키워드로 장소 검색(`/local-open/.../search/keyword`, 카카오맵) | 100,000건 | 2원/건 |
| 지도 Web(JS) SDK(`/maps-open/.../maps4`, 카카오맵) | 300,000건 | 0.1원/건 |

- ⚠️ **"카카오맵" 카테고리(지도 SDK·주소/키워드 검색 등)는 개발자 계정 기준 첫 번째로 활성화한
  앱에만 무료 쿼터가 붙는다.** 이 프로젝트 앱이 그 "첫 번째 앱"이 아니면 위 표의 무료량이 전부
  0이고 첫 호출부터 과금 — 콘솔 [쿼터] 탭에서 실제 무료 제공량이 0으로 뜨는지로 확인 가능.
  **카카오내비(길찾기)는 이 단서 없음**, 앱 무관하게 10,000/일 무료.

### 3-2. 월간 쿼터 — "무료 API Total" 공용 풀 (앱당 300만/월)

- 콘솔 [쿼터] > 월간 탭에 `[open][무료 API Total] 기본앱, 앱당 월쿼터 300만`으로 표시.
  카카오 디벨로퍼스 문서의 "월간 쿼터 — 전체 API 3,000,000건"과 같은 풀(콘솔 실측 기준).
- **길찾기·지도SDK·주소검색·키워드검색 등 서로 다른 API 호출이 전부 이 하나의 카운터에 합산된다**
  (실측: 그날 directions~20 + maps4~3 + address~2 + keyword~2 호출 → 월간 카운터 192로 반영).
  즉 "API별 일간 쿼터"와 "전체 API 월간 300만"은 **동시에 적용되는 독립된 두 제약**이지,
  일간 쿼터들을 합쳐서 300만이 되는 게 아니다(실제로 다 더해도 약 189만이라 300만에 못 미침).
- 문서엔 "추가 쿼터를 사용한 API 호출은 무료 제공 월간 쿼터를 차감시키지 않습니다"라고 돼 있어
  **유료로 넘어간(초과) 호출만 이 풀에서 빠진다**는 뜻으로 읽힘 — 무료 범위 내 호출은 실측대로
  이 풀에도 같이 잡힘. (반대로 "이 API 유형 자체가 통째로 월간 풀과 무관하다"는 해석은 실측과 배치돼 틀림)
- 이 프로젝트 규모(콘솔 실측 월 192건)로는 일간 쿼터든 월간 300만이든 여유가 압도적 — 실질 리스크 아님

## 4. 서버 쿼터 게이트 적용 현황 (2026-09-21)

Supabase `api_budget` 테이블(`day`, `api_type`, `used`) + `reserve_api_budget` RPC로 **API 종류별로 따로** 일일 상한을 건다(무료한도의 90%가 기본값, 각 env로 조정 가능). 원자적 예약 → 호출 → 실패 시 롤백 패턴은 셋 다 동일(`src/lib/api-budget.ts`의 `reserveApiBudget` 공용).

| API | api_type | 기본 상한(env) | 코드 위치 |
|---|---|---|---|
| 길찾기 | `directions` | 9,000/일(`ROUTE_DAILY_BUDGET`) | `src/lib/route-ranking.ts` |
| 주소 검색 | `geocode_address` | 90,000/일(`GEOCODE_ADDRESS_DAILY_BUDGET`) | `src/lib/kakao-geocode.ts` |
| 키워드 검색(폴백) | `geocode_keyword` | 90,000/일(`GEOCODE_KEYWORD_DAILY_BUDGET`) | `src/lib/kakao-geocode.ts` |

- 마이그레이션: `supabase/migrations/0003_api_budget_per_type.sql` (0002는 `directions` 전용 단일 카운터였음 — api_type 컬럼 추가해 종류별로 분리)
- 주소검색 예산 초과: 검색 자체를 하드 에러로 막음(`GeocodeUnavailableError('over_budget')`, HTTP 429) — 매 검색마다 항상 나가는 1차 호출이라
- 키워드검색 예산 초과: 에러 안 띄우고 조용히 빈 결과 반환 — 주소검색 실패 시에만 쓰는 폴백이라 덜 치명적으로 처리
- Supabase 미설정 시: geocode도 route-ranking과 동일하게 기능 자체를 비활성화(fail-closed) — 이 기능은 어차피 Supabase 없인 길찾기 단계에서 막히므로 geocode만 열어둘 이유가 없음

지도 SDK 쿼터(300,000/일)는 서버 호출이 아니라 브라우저에서 SDK 스크립트를 로드하는 것뿐이라 서버 예산 게이트 대상이 아님 — 앱 로드 횟수가 곧 소진량.
