# 5. 보존·삭제 정책

## 삭제 경로 세 가지 (범위 정리)

| 방식 | 범위 | 어디서 |
|---|---|---|
| 하트 다시 누르기(해제) | 학교 1개 | [02_토글UI.md](02_토글UI.md)의 다섯 곳 어디서든 — **1차** |
| 목록에서 항목별 삭제 | 학교 1개 | 관심학교 목록 화면 — **2차**(학교 비교 탭, [03](03_목록보기.md)) |
| 전체 삭제 | 관심학교 전체 | `/settings` 페이지 — **1차** |

"해제"와 "전체 삭제"만 1차에 포함된다 — 목록 화면 자체가 2차라 "목록에서 항목별 삭제"는
자연히 2차로 같이 넘어간다. 관심학교를 개별로 빼고 싶으면 1차에서도 상세 패널을
열어 하트를 다시 누르면 되므로, 기능이 아예 없는 건 아니다.

## 자동 만료 없음

`use-user-settings-store`의 근무지역·희망지역·거주좌표·엑셀데이터는 `savedAt` 기준
20일이 지나면 재방문 시 자동 전체 삭제된다(`settings-retention.ts`, `RETENTION_DAYS`).
이건 그 항목들이 **개인 식별에 가까운 정보**(현재/희망 근무지, 거주지 좌표, 인사기록)라
"공용 PC에서 오래 남으면 안 된다"는 전제에서 나온 정책이다.

관심학교는 성격이 다르다 — "어떤 학교가 마음에 들었는지" 정도라 민감도가 낮고, 오히려
**자동으로 사라지면 기능 자체가 무의미**해진다(북마크가 20일마다 리셋되면 아무도 안 씀).
그래서 관심학교 스토어([01_저장방식.md](01_저장방식.md))에는 만료 로직을 넣지 않는다
— 사용자가 직접 하트를 해제하거나, 아래 "전체 삭제"를 누르기 전까지 계속 남는다.

## `/settings` 페이지 연동 — ✅ 완료

기존 "저장된 정보 삭제" 버튼(`settings-container.tsx`)은 PII 자동삭제 대상 전체를
지우는 용도라 관심학교는 그 범위에 넣지 않는다. 대신:

- 상단 "개인정보 관리 안내" 배너에 **"관심학교는 자동 삭제 대상이 아니다"**를 명시하는
  문구를 추가 — 사용자가 "다른 설정처럼 20일 뒤 알아서 지워지겠지"로 오해하지 않게.
- 관심학교는 메인 설정 카드(학교급·시군·거주지 등)와 성격이 달라서(자동 삭제 안 됨,
  학교비교 탭의 기반 데이터) **별도 상자**로 분리 — "관심학교" 제목 + "자동 삭제되지
  않음" 뱃지 + "N개 저장됨 · 목록 보기" 버튼(박스 전체 클릭) + "전체 삭제" 텍스트 버튼.
- **관심학교 목록 모달**(`favoritesListOpen`) — "N개 저장됨" 버튼을 누르면 뜬다.
  `useChungbukSchools()`로 전체 학교 데이터를 받아 `favoriteCodes`(코드만 있음)를
  실제 `School` 객체(학교명·학교급·시군)로 매핑해 보여준다 — **조회 전용**, 목록에서
  개별 삭제는 아직 없음(위 표의 "2차" 항목, 학교비교 탭에서 다룰 예정). `/statistics`를
  먼저 방문했으면 React Query 캐시(`staleTime: Infinity`)를 그대로 재사용해 추가 요청 없음.

공용 PC 사용 시 개인정보 안내 문구("공용 PC·공용 기기에서는 정보 저장에 주의를
기울려 주세요")는 관심학교에도 그대로 적용된다 — 민감 정보는 아니지만 "내가 이
학교들에 관심 있다"는 것 자체가 남의 눈에 보이길 원치 않을 수도 있으니.

## 공용 스토어 vs 개별 페이지 상태

관심학교 스토어는 `/statistics`뿐 아니라 `/settings`(개수 표시·삭제)에서도 읽으므로,
페이지 이동과 무관하게 항상 최신값을 읽을 수 있어야 한다 — zustand persist 전역
스토어([01_저장방식.md](01_저장방식.md))를 쓰는 이유 중 하나이기도 하다(컴포넌트
로컬 state로는 페이지 이동 시 유지가 안 됨).
