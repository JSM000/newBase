# 관심학교 기능 — 구현 계획 (목차)

> 용어: 처음엔 "즐겨찾기"로 부르다가, 스위치 라벨을 4글자의 명확한 단어로 바꾸면서
> **"관심학교"**로 용어 자체를 통일했다(문서·대화 전부). 코드의 파일명·변수명·DB
> 테이블명(`use-favorite-schools-store.ts`, `FavoriteToggleButton`, `favoriteCodes`,
> `school_favorites` 등)은 바꾸지 않았다 — 그건 내부 식별자일 뿐이라 사용자가 보는
> 말(라벨·문서·대화)만 관심학교로 맞추면 충분하다고 판단.

## 배경 / 목적

통계지도(`/statistics`)에서 여러 학교를 둘러보다가, 마음에 드는 학교를 표시해뒀다가
나중에 다시 모아 볼 수 있게 한다. 서버 저장 없이 **이 브라우저에만** 남는다 — 기존
"개인정보 보호 원칙"(`CLAUDE.md`)과 같은 방향이지만, 관심학교 자체는 주소·재직정보 같은
개인 식별 정보가 아니라 "학교 코드 목록"일 뿐이라 그 불변조건과 직접 충돌하지는 않는다.

**이 기능은 향후 "학교 비교" 탭(관심학교들끼리 통계를 나란히 비교)의 기반이다.**
비교 탭 자체의 설계·구현은 **2차** — 별도 계획 문서(`_refs/학교비교_구현계획/`, 아직 미작성)로
그때 다룬다. 이번 문서(관심학교)는 **1차**로, "관심학교를 선정하고, 어디서든 그
표시를 확인할 수 있는" 기반 기능까지만 다룬다 — 관심학교 목록을 한 화면에 모아 보는 UI
자체는 비교 탭에서 구현하므로 이번 1차에는 포함하지 않는다.

- **저장 위치**: 브라우저 `localStorage`만. 서버로 전송하지 않음.
- **기술 방식**: zustand `persist` — `src/store/use-user-settings-store.ts`와 같은 패턴을
  재사용하되, **별도 스토어**로 분리한다 (이유: [01](01_저장방식.md)).

## 구현 완료 사항

1. **전용 zustand 스토어**(`use-favorite-schools-store.ts`)로 분리하고, 기존
   `use-user-settings-store`(자동 만료 20일)와는 **독립적으로 만료 없이 보존**한다.
   → [01](01_저장방식.md), [05](05_보존정책.md)
2. 관심학교 토글/표시는 **다섯 곳**에 노출한다: 상세 패널 헤더(토글), 순위 목록 각
   행(토글), 길찾기 결과 목록 각 행(토글), 지도 개별 마커(표시 전용 — 코너 배지),
   지도 마커 호버 툴팁(표시 전용 — 이름 옆 빨간 ♥). → [02](02_토글UI.md)
3. `/settings`에 관심학교 개수 표시 + "전체 삭제" 버튼. → [05](05_보존정책.md)
4. 통계지도 필터 바에 **"관심학교"** 스위치(지도·학교 순위 대상을 좁힘, 기존 필터와
   교집합) + 길찾기 도착지 팝업에 **"관심학교만 검색하기"** 버튼(박스 전체가 버튼,
   켜면 시·군/학교급/설립구분 select를 아예 숨기고 저장된 관심학교 전체가 대상, 서버
   (`/api/route-ranking`)로 관심학교 코드 목록을 보내는 첫 사례 — 학교 코드는
   개인정보 아님). → [04](04_필터지도연동.md)

## 서버 집계 확장 — ✅ 완료 (원래 계획 범위 밖, 추가 요청으로 구현)

"관심학교로 등록된 횟수를 별점처럼 DB에 모아 참고 지표로 쓰자"는 요청으로, 로컬
전용이던 관심학교가 **부분적으로** 서버와 연결됨. 별점(`school_ratings`)·조회수
(`school_views`)와 같은 원칙(`0001_school_social.sql`)을 그대로 따르는 새
테이블/뷰/RPC(`0004_school_favorites.sql`):

- `school_favorites(client_id, school_code)` — 원본 행, anon 직접 접근 불가(RLS + revoke).
- `school_favorite_stats` 뷰 — `school_code`별 `favorite_count`만 공개.
- `add_school_favorite`/`remove_school_favorite` RPC — 관심학교는 값이 아니라 on/off라
  별점의 upsert 대신 insert/delete. 멱등(이미 있으면 무시, 없으면 그냥 넘어감).

**로컬 스토어(01)는 그대로 순수 로컬** — `FavoriteToggleButton`이 로컬 토글 직후
`useSyncFavorite`(`use-school-social.ts`, `useRateSchool`과 동일한 낙관적 업데이트 +
rollback 패턴)을 같이 호출해서 서버 집계에도 반영한다. Supabase 미설정이면 이 동기화만
조용히 스킵 — 로컬 관심학교 자체는 항상 그대로 동작(불변조건 유지).

- **버그(실측·수정됨)**: 관심학교를 누르면 조회수가 1 줄어들어 보였다 — 원인은
  `useSyncFavorite`의 `onSettled`가 `invalidateQueries`로 즉시 refetch를 했는데,
  `/api/school-social`가 CDN에 `s-maxage=60`으로 캐시돼 있어서 막 반영된 조회수 낙관적
  업데이트를 stale 응답이 덮어써버린 것. `useRateSchool`엔 있는 `onSettled` invalidate를
  `useSyncFavorite`에서는 빼고, `useRecordView`처럼 낙관적 값을 그대로 두고 자연스러운
  다음 refetch(포커스 복귀 등)에서 수렴하게 바꿔 해결.
- 상세 패널 헤더에 조회수 옆으로 **관심 수**도 표시(`school-detail-panel.tsx`,
  빨간 채움 하트 아이콘 + `social.favoriteCount`) — `socialEnabled`일 때만.

집계된 수는 `FAVORITE_INDICATOR_KEY`(`school-indicators.ts`, 표시 라벨 "관심학교 등록
수")로 등록해 별점·조회수와 나란히 "표시·순위 기준" 드롭다운의 "커뮤니티" 그룹에 추가
— 지도 색칠·범례·학교 순위 전부 기존 지표와 동일한 경로를 그대로 탄다. 경계값
(1/3/6/12)은 다른 커뮤니티 지표처럼 1차 추정치.

**아이콘/색 변경도 같이 진행**: 별점과 모양이 겹친다는 지적으로 토글 아이콘을
별 → **하트**로, 색은 amber(호박색) → 처음엔 pink-500을 썼다가 "색이 이상하다, primary보다
빨강에 가깝게"라는 피드백으로 **red-600(`#dc2626`, primary `#e77474`와 같은 붉은 계열이되
더 진하고 순수한 빨강)**으로 재조정했다. 상세는 [02_토글UI.md](02_토글UI.md) 상단 업데이트
노트 참고.

## 2차로 넘기는 사항 (설계만 기록, 구현 안 함)

1. **관심학교 목록을 한 화면에 모아 보는 UI** — 학교비교 탭이 이 목록을 그대로 기반
   데이터로 쓸 예정이라, 목록 UI 자체를 비교 탭과 같이 설계하는 게 중복이 없다.
   → [03](03_목록보기.md)
2. 관심학교 목록에서 **개별 항목 삭제**(학교비교 탭 안에서) — 지금은 각 표시 위치의
   하트 아이콘을 다시 눌러 해제하는 것까지만, 목록 화면 자체가 없으므로 "목록에서 삭제"는
   비교 탭과 함께 구현. → [05](05_보존정책.md)
