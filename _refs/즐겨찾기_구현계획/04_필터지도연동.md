# 4. 필터 연동 — ✅ 완료

지도 마커·툴팁에 관심학교를 **표시**하는 것은 [02_토글UI.md](02_토글UI.md) D·E, 아래
두 가지(관심학교를 **필터 조건**으로 쓰는 것)는 이 문서. 전부 구현 완료.

## A. 통계지도 "관심학교" 필터

`statistics-container.tsx`의 `filtered`(시·군/학교급/설립구분/검색어 필터)에 관심학교
조건을 **교집합**으로 추가 — 켜면 "지금 필터 + 관심학교"만 보인다(시·군을 "청주시"로
두고 켜면 청주시 안의 관심학교만). `showAllMarkers`/`showBoundaries`와 같은 자리(필터
바 지도 컨트롤 줄)에 스위치 추가, 관심학교 0개면 비활성화.

## B. 길찾기(CommutePanel) 대상 필터에 "관심학교만 검색하기" 옵션

A와 달리 **교집합이 아니라 대체** — 켜면 시·군/학교급/설립구분 자체를 무시하고
**저장된 관심학교 전체**(지역·학교급 구분 없이)가 대상이 된다(관심학교는 여러
시·군·학교급에 걸칠 수 있어서 그 필터들과 같이 못 씀). "도착지 조건" 팝업 안에 두며,
UI가 두 차례 바뀌었다:
1. 처음엔 라벨 "관심학교만 대상으로" + 작은 `Switch`.
2. "박스 전체가 버튼이면 좋겠다"는 요청으로 `<button>` 하나로 바꿈(`aria-pressed`로
   상태 표시, 켜지면 `border-primary bg-primary text-white`로 꽉 채움) — 라벨도
   "관심학교만 검색하기"로 변경.
아래 `SchoolScopeFields`(설립구분/학교급/시·군)는 켜지면 **아예 숨긴다**(처음엔
흐리게만 했는데(`opacity-40 pointer-events-none`), "지금 뭘로 대상을 고르는지 헷갈린다"는
피드백으로 조건부 렌더링(`{!commuteFavoritesOnly && <SchoolScopeFields .../>}`)으로
바꿈 — 꺼지면 다시 나타난다). 페이지 진입 시 기본값은 항상 꺼짐(`useState(false)`).

**구현**: 관심학교는 클라이언트 전용 상태라 서버(`route-ranking.ts`의 `computeRanking`)가
이 대상을 알려면 학교 코드 목록 자체를 요청 바디에 실어 보내야 한다 —
`RouteRankingRequest.favoriteCodes?: string[]`를 추가하고, 1개 이상 있으면
`schulKndCode`/`sigungu`/`ownership`을 완전히 무시한 채
`ALL_SCHOOLS.filter(s => favoriteCodes.includes(s.schulCode))`로 대상을 정한다.
`/api/route-ranking`은 `favoriteCodes`가 있으면 그쪽 검증(문자열 배열, 524개— 충북 전체
학교 수 — 초과분은 클라 변조로 보고 자름)만 하고 기존 시·군/학교급 검증은 건너뛴다.

**왜 목록 자체를 보내야 하는가 (client_id로 서버 조회하는 대안과 비교)**: 실제 카카오
길찾기 호출과 일일 예산 관리는 `KAKAO_REST_API_KEY`/`SUPABASE_SECRET_KEY`가 서버 전용이라
반드시 서버에서 돈다 — 그래서 "어떤 학교들이 대상인지"도 서버가 알아야 하는데, 관심학교는
시·군처럼 값 하나가 아니라 "이 브라우저가 관심학교로 등록한 정확한 학교 목록"이라 서버가 스스로
알 방법이 없다. 기술적으로는 `client_id`만 보내고 서버가(서비스 키는 RLS를 우회하므로)
`school_favorites` 테이블을 직접 조회하는 대안도 가능하긴 하다. 그런데 [01_저장방식.md](01_저장방식.md)의
설계상 **로컬 스토어가 진짜 소스이고 DB(`school_favorites`)는 집계용 미러일 뿐**이라 —
Supabase 미설정이었거나 동기화가 한 번 실패했으면 DB 쪽이 로컬보다 못할 수 있다. 그래서
"화면에 지금 보이는 관심학교 그대로" 계산하려면 클라이언트가 들고 있는 배열을 그대로
보내는 지금 방식이 더 정확하다. 학교 코드 자체는 개인정보가 아니라 CLAUDE.md 불변조건과는
무관 — 그래도 이 문서의 "서버로 안 보낸다" 원칙에서 벗어나는 지점이라 여기 명시적으로
기록해둔다.

## 순위 목록·길찾기 목록의 토글과 필터의 관계

각 목록 행에 이미 관심학교 토글이 있으므로([02_토글UI.md](02_토글UI.md) B·C), 사용자는
순위·길찾기 결과를 보다가 바로 관심학교에 추가할 수 있다 — 이게 있으면 "관심학교" 필터(A)의
필요성이 상대적으로 줄어들지만, B(길찾기 대상 필터)는 그것과 별개로 "관심학교끼리
비교"라는 새로운 사용 목적이라 독립적인 가치가 있다.
