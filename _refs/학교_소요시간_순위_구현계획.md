# 학교 소요시간 순위 기능 구현 계획

> 목표: 사용자가 **집주소 + 학교급(초/중/고) + 시군구**를 입력하면, 그 시군구의 해당 학교급
> 학교까지 **자동차 소요시간**을 계산해 **가까운 순 → 먼 순**으로 순위를 보여준다.
> 순위에서 학교를 누르면 **집→그 학교 경로를 지도에 표시**한다.
> 성격: 참고용이지만 **"우리 집에서 가장 가까운 학교"가 핵심 질문**이라 순위 정확도는 챙긴다.
> **무료 API 한도 내 운영이 최우선 제약.**
> 관련 문서: `_refs/학교통계_지도_구현계획.md` (지도·학교 데이터셋), `_refs/학교_별점_조회수_구현계획.md` (Supabase·라우트 핸들러 패턴)

## 1. 범위

**포함 (v1)**

- 입력: 집주소(문자열). 대상 학교급·시군구는 **통계 지도 필터바 값**을 그대로 사용
- 그 시군구·학교급 학교에 대해 자동차 길찾기 → `소요시간` 순위 (가까운/먼 순 토글)
- **직선거리(haversine) 상위 `ROUTE_MAX_PER_QUERY`개만 실측**, 나머지는 직선거리순으로 함께 표시.
  "나머지도 계산" 버튼으로 예산·쿨다운 한도 내 다음 배치 (클라가 결과 병합)
- 순위 응답에 **경로 폴리라인 인라인 포함** → 클라 메모리에 보관, 학교 클릭 시 추가 API 없이 지도에 그리기
- **서버 전역 일일 호출 상한**(`api_budget`) — 소진되면 그날 신규 계산 차단(안내 배너)
- **클라 재검색 제한** — 검색 1회 성공 후 30초간 재검색·"나머지 계산" 버튼 비활성 (localStorage)

**제외 (→ 10. 추후 과제)**

- 대중교통·도보·자전거 경로 (자동차만)
- 출발 시각/실시간 교통 반영
- 다중 목적지 길찾기 API (제휴 승인 필요 + 과금 카운트 불명확 — 3번 참고)
- **결과·주소 캐시** (`route_cache`·`geocode_cache`) — 과한 인프라라 v1에서 안 둠. 매 검색 = 카카오 호출
- 사용자별 한도, 로그인, 즐겨찾기

## 2. 결정 사항 (요구사항 확정)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 소요시간 정확도 | **지오코딩 실좌표 그대로** 출발점 (격자 스냅 없음). 시간대·실시간 교통 미반영, ±2분 오차 허용 |
| 2 | 실측 대상 | 직선거리 상위 `ROUTE_MAX_PER_QUERY`개(**기본 20**). 나머지는 직선거리순 표시(소요시간 공란). "나머지도 계산" → 다음 배치, 클라가 병합 |
| 3 | 사용 API | **카카오모빌리티 자동차 길찾기(1:1)** — 무료 10,000건/일, 셀프서비스. 다중 목적지 API는 미사용 |
| 4 | 순위 계산 시 응답 | **full 응답** (경로 폴리라인 포함, tolerance ~50m 단순화). 응답에 인라인 → 클라 메모리 보관. `summary=true` 안 씀(요금 동일) |
| 5 | 경로 재사용 | 별도 `/api/route-path` 없음. 클릭한 학교의 `path`를 이미 받은 응답에서 꺼내 그림 |
| 6 | 캐시 | **없음.** `route_cache`·`geocode_cache` 안 만듦(과한 인프라). 매 검색 = 카카오 호출 |
| 7 | 서버 상한 | `api_budget` 전역 카운터. 기본 `ROUTE_DAILY_BUDGET=8000`. 이번 배치 건수만큼 차감, 실패분 롤백 |
| 8 | 상한 초과 시 | 신규 계산 차단. `overBudget: true` → 패널에 "오늘 한도 소진" 배너. 그날은 그 이상 계산 안 됨 |
| 9 | 클라 재검색 제한 | 검색 **성공** 후 30초 쿨다운 (`localStorage` `commute:last-search-at`). 계산·"나머지 계산" 버튼 비활성 + 카운트다운. 실패(지오코딩 등)는 쿨다운 안 검 |
| 10 | Supabase 접근 | `api_budget` 접근만 — 서버 라우트 전용, **Secret key**(`sb_secret_...`, RLS 우회) |
| 11 | env 없을 때 | UI 게이트 없음. `[길찾기]` 버튼 항상 노출, 키 미설정이면 계산 시 서버 503(`not_configured`) → 패널 에러 |

## 3. 외부 API 비용 통제 전략

> 카카오 API 무료 쿼터 상세(길찾기/지오코딩/지도SDK 일간 한도, 월간 300만 공용 풀, "첫 번째 앱만
> 무료" 단서 등)는 별도 문서 **`_refs/카카오_API_쿼터.md`** 참고. 이 절엔 그 숫자를 바탕으로 이
> 기능이 실제로 쓰는 통제 전략만 남긴다.

출발 좌표를 격자에 스냅하지 않으므로 **사용자 간 캐시 공유는 사실상 없다**. 대신:

1. **haversine 사전 필터** (가장 큰 레버) — 학교 좌표는 데이터셋에 이미 있으므로 API 없이 직선거리를 구해 **가까운 20개만 실측**. "우리 집에서 가장 가까운 학교"라는 핵심 질문엔 상위 10~15개면 충분하고, 먼 학교는 직선거리 순위 ≈ 도로 순위라 오차가 무의미
2. **서버 일일 예산 게이트** (`api_budget`) — 무료 한도를 넘는 순간 신규 계산을 막아 요금 청구 차단
3. **클라 30초 재검색 제한** — 같은 사람이 연달아 두드리는 걸 UX 레벨에서 완화 (우회 가능, 요금 방어선은 2번)

캐시는 안 둔다. 매 검색 = 카카오 호출 1(지오코딩) + ≤20(길찾기). `summary=true`는 요금을 안 줄이므로
(과금 = 호출 건수) full 로 받아 경로까지 응답에 실어 보낸다 — 클라가 메모리에 들고 클릭 시 재사용.
관외(비청주) 초등 학교 수 15~46개라 `ROUTE_MAX_PER_QUERY=20`이면 대부분 시군구는 전 학교 실측.

### 4-1. 흐름

```
[통계 지도 /statistics — 필터바에서 설립구분 + 시·군 + 학교급 선택 후 [길찾기] 클릭]
  CommutePanel: 집주소 입력 + [검색]
        │  POST /api/geocode { address }         ← ① 지오코딩만, 길찾기 예산과 무관
        ▼
[서버: 카카오 주소검색(size=5) → 0건이면 키워드검색(size=5) 폴백]
        │  { candidates: [{ label, roadAddress, addressType, source, lat, lng }, ...] }
        ▼
[클라이언트] markSearched()(30초 쿨다운 시작, 후보 조회 시점에 기록) + 후보 목록 렌더
  사용자가 후보 하나를 직접 클릭해 출발지 확정 (카카오 1위 자동 채택 안 함 — REGION 같은
  부정확 매칭이 1위로 올 수 있어서. addressType 배지로 "동·읍·면 단위 근사치" 안내)
        │  POST /api/route-ranking { origin:{lat,lng}, schulKndCode(=필터 level), sigungu,
        │      ownership(=필터 설립구분), offset }         ← ② 여기서부터 길찾기 예산 소비
        ▼
[서버 라우트 (SUPABASE_SECRET_KEY, KAKAO_REST_API_KEY 보유)] — 지오코딩 없음, origin 그대로 사용
  1) 대상 학교 = render.json 정적 import 에서 (sigungu, schulKndCode, ownership, position 있음) 필터
  2) 각 학교와 haversine 거리 → 오름차순 정렬
  3) 이번 배치 = targets[offset : offset + ROUTE_MAX_PER_QUERY]
  4) reserve_api_budget(today, 배치크기, ROUTE_DAILY_BUDGET) 원자적 예약
       - NULL(한도 초과) → 길찾기 안 하고 직선거리만으로 응답 (overBudget: true)
  5) 배치 학교에 자동차 길찾기 1:1 (full, 동시 6개). 실패 건은 예산 롤백(음수 예약)
  6) 전체 targets 를 매핑 → 배치에서 라우팅된 학교만 { durationSec, distanceM, path }, 나머지는 null
  7) compareByCommute 로 정렬(소요시간 오름차순 → 없으면 직선거리) → 반환
        │  { origin, results:[{ schulCode, schulNm, address, position, straightKm,
        │      durationSec|null, distanceM|null, path|null }],
        │    measuredCount, totalCount, remainingCount, overBudget }
        ▼
[클라이언트]
  onSuccess → 컨테이너가 결과 병합(offset>0 시 이전과 merge) — 쿨다운은 이미 ①에서 기록됐으므로 재기록 안 함
  목록 행 클릭 → commuteSelected 갱신 → routeOverlay 메모가 그 학교의 path 를 꺼냄
  KakaoMap: routeOverlay.origin = 집 마커, path 있으면 Polyline + 경로에 bounds, 없으면 집+대상학교에 bounds
  [나머지 N곳도 계산] → POST { origin(=확정된 출발지 그대로), ..., offset: measuredCount }

```

### 4-2. haversine (`src/lib/route-origin.ts`, 클라·서버 공용)

- `haversineKm(a, b)` — 학교 데이터셋 좌표만으로 계산(API 0). 상위 N 선별 + "직선거리" 표시값
- `compareByCommute(a, b)` — 소요시간 있는 학교 시간 오름차순, 없으면 뒤에 직선거리순. 서버 정렬 + 클라 병합 후 재정렬 공용
- **격자 스냅 없음** — 지오코딩 실좌표 그대로 길찾기 출발점. 정확도 손실 0

### 4-3. 예산 게이트 (`api_budget` + RPC) — 유일한 서버측 방어선

**왜 우리가 세야 하나** — 카카오는 응답에 잔여 쿼터를 **안 준다**(헤더·API 없음, 콘솔에서 수동 확인만).
자동차 길찾기는 무료 10,000/일을 넘겨도 **막지 않고 자동 8원/건 과금**한다. → 백엔드가 직접 카운트.

- 호출 **직전에** `reserve_api_budget(today, 배치크기, ROUTE_DAILY_BUDGET)` 원자적 예약. 초과면 호출 안 함
- 실패분(타임아웃 등) `M′`건은 `reserve_api_budget(today, -M′, 2e9)`로 롤백
- **RPC 자체 방어** (service_role 만 부르지만 서버 버그 대비): ① `p_n = 0 or abs(p_n) > 500` → 예외
  ② 테이블 `check (used >= 0)` — `used` 가 음수로 가면 `used + p_n <= p_limit` 가 항상 참이 돼 게이트가
  조용히 무력화되므로 DB 레벨에서 차단. 잘못된 입력·CHECK 위반은 **예외**로 튀어 카운터 불변,
  서버는 로그만. (롤백이 실패해도 카운터가 살짝 부풀 뿐 = 실제보다 보수적 = 안전)
- 리셋: `day` PK(KST 기준) → 자정 넘으면 새 행. 크론 불필요
- 우리 카운터 ≠ 카카오 실측(재시도 오차) → 기본 8000(무료의 80%)으로 여유. 대시보드 결제 알림 병행 권장

## 5. 스키마 (`supabase/migrations/0002_route_ranking.sql`)

캐시 테이블은 없다. `api_budget` 1개 + RPC 1개뿐.

```sql
create table if not exists public.api_budget (
  day  date primary key,
  used int  not null default 0 check (used >= 0)   -- 음수 = 게이트 무력화 → DB 레벨 차단
);
alter table public.api_budget enable row level security;   -- 정책 없음 = anon 접근 거부
-- 이미 만들어진 테이블에도 CHECK 보강 (idempotent) — 실제 SQL 파일은 do $$ ... $$ 블록 참고

create or replace function public.reserve_api_budget(p_day date, p_n int, p_limit int)
returns int language plpgsql security definer set search_path = public as $$
declare v_used int;
begin
  if p_n = 0 or abs(p_n) > 500 then          -- 서버 버그로 -1000000 같은 값이 와도 즉시 거부
    raise exception 'reserve_api_budget: p_n out of range (%)', p_n;
  end if;
  insert into public.api_budget (day, used)
  select p_day, p_n where p_n <= p_limit
  on conflict (day) do update
    set used = api_budget.used + p_n
    where api_budget.used + p_n <= p_limit
  returning used into v_used;
  return v_used;   -- NULL = 한도 초과(반영 안 됨). 예외 = 범위 밖/CHECK 위반 → 카운터 불변
end; $$;

revoke all on function public.reserve_api_budget(date, int, int) from public, anon, authenticated;
grant execute on function public.reserve_api_budget(date, int, int) to service_role;
```

**env 추가** (`.env*` 커밋 금지 — 기존 규칙):

```
KAKAO_REST_API_KEY     # 서버 전용. 모빌리티 길찾기 + 로컬 주소검색
SUPABASE_SECRET_KEY    # 서버 전용. Supabase 대시보드 > API Keys > Secret key (sb_secret_...) 만
ROUTE_DAILY_BUDGET=8000  # (선택) 서버 전역 일일 길찾기 상한
ROUTE_MAX_PER_QUERY=20   # (선택) 1회 조회당 실측 학교 수 (haversine 상위 N)
```

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_KAKAOMAP_API_KEY`(지도)는 기존 것 재사용
- `SUPABASE_SECRET_KEY` 는 `sb_secret_` 로 시작해야 함 — 아니면 서버가 명확한 에러로 거부
  (publishable/anon 키나 구형 service_role JWT 붙여넣기 실수 방지)
- **노출 게이트 없음** — 위 키를 다 넣고 마이그레이션을 돌리면 동작.
  덜 넣은 상태로 폼을 제출하면 서버가 503 + "아직 설정되지 않았습니다" 반환
- 카카오 디벨로퍼스에서 **모빌리티 자동차 길찾기 활성화** + REST 키 발급 필요
- `.env.example`은 샌드박스 쓰기 금지로 생성 못 함 — 위 목록으로 대체

**터미널에서 직접 주입해도 되는가 → 된다** (기존 프로젝트 관례와 동일):

```
KAKAO_REST_API_KEY=... SUPABASE_SECRET_KEY=sb_secret_... \
NEXT_PUBLIC_KAKAOMAP_API_KEY=... NEXT_PUBLIC_SUPABASE_URL=... npm run dev
```

- `dev` 는 서버·클라 변수 모두 시작 시점 환경에서 읽음 → 문제 없음
- ⚠️ **프로덕션 주의**: `NEXT_PUBLIC_*` 는 **`next build` 시점에 코드에 인라인**된다. `next start` 때
  주입하면 이미 늦음. `KAKAO_REST_API_KEY` / `SUPABASE_SECRET_KEY`(서버 전용)는 라우트
  핸들러에서 런타임에 읽으므로 `next start` 때 주입해도 됨. Vercel 은 환경변수 설정이면 다 해결
- `.env.local` 이 없어도 됨 (Next 가 없는 파일은 그냥 건너뜀)

### 5-1. 계획이 진행하며 바뀐 것 (기록)

- **UI 게이트 폐기**: `NEXT_PUBLIC_COMMUTE_ENABLED` 플래그 → 서버 키검증 → "서버 503이 이미
  안전장치, 운영자 1인"이라 전부 제거. 버튼 항상 노출.
- **위치**: 별도 `/commute` 페이지로 만들었다가 → 요구는 **통계 지도 안의 패널**이라 이전.
- **캐시 폐기**: `route_cache`·`geocode_cache`(+`/api/route-path`, `useRoutePath`, 좌표 정규화
  `originKey`, purge 배치)까지 갔다가 "과한 인프라"라 제거. 경로는 순위 응답에 인라인,
  남용은 클라 30초 쿨다운 + `api_budget` 만.
- Supabase 키: `SUPABASE_SERVICE_ROLE_KEY` → `SUPABASE_SECRET_KEY` (Secret key `sb_secret_` 전용).
- **설립구분 필터 추가**: 길찾기 대상이 시·군+학교급만 따르다가, 지도·순위 패널과 기준이
  달라 "필터엔 안 보이는데 왜 길찾기 대상엔 있냐"는 혼란이 생겨서 `ownership`도 반영.
  `computeRanking`의 대상 필터에 `fondScCode` 조건 추가, 요청·검증·패널 표시 문구까지 전파.
- **주소 자동 확정 → 후보 선택으로 전환**: v1은 지오코딩 1위 결과를 검증 없이 바로 썼는데,
  `address_type`이 `REGION`(동 단위)이어도 그대로 채택돼 부정확할 수 있었음. `/api/geocode`를
  분리해 최대 5개 후보(+ `address_type`/`source` 배지)를 보여주고 사용자가 직접 고르게 함.
  후보 조회는 호출 1번이라 비용 증가 없음(응답 개수는 과금과 무관) — 다만 "항상 주소+키워드
  둘 다 조회"로 가면 호출이 2배 되므로, 기존처럼 주소검색 0건일 때만 키워드 폴백 유지.
  `RouteRankingRequest`도 `address` 대신 확정된 `origin` 좌표를 받도록 바뀌어, "나머지도 계산"
  때 매번 재지오코딩하던 낭비도 같이 없어짐. 30초 쿨다운은 후보 조회(②가 아니라 ①) 시점에 기록.

- 후보 클릭 즉시 그 좌표로 길찾기 실행(추가 지오코딩 없음)
- 결과 목록: 실측 `1. ○○초등학교  12분 · 6.4km` / 미실측 `21. △△초등학교  직선 9.7km`(회색)

**지도 (`kakao-map.tsx` 에 `routeOverlay` prop 추가)**

- `routeOverlay = { origin, path } | null` (컨테이너가 `useMemo` 로 안정화해서 전달)

- 학교 마커/클러스터·경계선 등 기존 지도 동작은 그대로. 길찾기 모드에서 학교 마커를 클릭하면
  (그 결과에 있는 학교면) 상세로 안 가고 경로만 선택

**상한 초과 배너**

- `overBudget`면 상단에 "오늘 무료 경로 계산 한도를 모두 사용했어요. 이미 계산된 학교는 순위에 표시되며, 나머지는 내일 다시 시도해 주세요."

### 7-1. API 키 보안 점검 (v1 구현 확인 결과)

| 항목 | 상태 |
|---|---|
| Secret/REST 키 쓰는 코드가 `'use client'` 인가 | **아니오.** `supabase-server.ts` / `route-ranking.ts` / `kakao-geocode.ts` / `kakao-directions.ts` 모두 서버 모듈. 클라가 import 하는 곳 없음(grep 확인). `route-origin.ts`(haversine·compare)만 클라·서버 공용인데 키를 안 만짐. `supabase-server.ts` 상단에 `typeof window` 가드 |
| 키가 브라우저 번들에 들어가나 | **아니오.** `SUPABASE_SECRET_KEY` / `KAKAO_REST_API_KEY` 는 `NEXT_PUBLIC_` 접두어가 없어 Next.js 가 클라이언트 코드에 인라인하지 않음. 서버 그래프(라우트 핸들러)에서만 참조. `supabase-server.ts` 에 `typeof window` 가드 + `sb_secret_` 접두어 검증 |
| 응답·로그에 키 노출 | 없음. 에러 응답은 일반 메시지, `console.error` 는 Supabase 에러 객체·HTTP status 만 |
| anon/publishable 키로 예산 조작 가능? | 불가. `api_budget` 은 RLS on + 정책 없음, `reserve_api_budget` 는 `revoke ... from public, anon, authenticated` + `grant execute ... to service_role`(Postgres 역할 — Secret key 가 이 역할로 매핑됨) |
| 엔드포인트 무인증 노출 | 맞음(앱 전체가 무인증). 도착지는 검증된 524개 학교로 한정, 최악은 하루치 예산 소진(요금 초과 아님) → v1 감수, 레이트리밋은 10. 추후 |
| 지도 JS 키(`NEXT_PUBLIC_KAKAOMAP_API_KEY`) | 원래 공개용. 카카오 콘솔에서 **도메인 화이트리스트**로 보호(기존 설정 그대로) |

## 8. 네트워크·비용 예상

캐시가 없으니 **검색 1회 = 지오코딩 1 + 길찾기 ≤ K**(K=`ROUTE_MAX_PER_QUERY`=20). 경로 클릭은 0(응답에 포함).

**일일 무료 한도(길찾기 10,000, 예산 기본 8,000)로 소화 가능한 검색 수**

| K | 하루 검색 수 |
|---|---|
| 20 (관외 초등 대부분 전 학교) | **~400회/일** |
| 15 | ~530회/일 |
| 충주 초등 46 (상한 해제) | ~170회/일 |

- 클라 30초 쿨다운 → 1인이 하루에 낼 수 있는 검색은 최대 ~2,880회(24h/30s)지만 현실적으론 수 회
- 초과 시: `overBudget` → 신규 계산 차단, **요금 청구 없음**. 그날 늦게 온 사용자는 직선거리만 봄
- 지오코딩: 검색 수와 비슷(~수백/일). 카카오 로컬 무료 쿼터 내
- **DB**: `api_budget` 하루 1행. 용량 걱정 전무
- 트래픽이 400회/일을 넘기면: ① K 축소 ② 다중 목적지 API 제휴 ③ IP 레이트리밋 (10. 추후)
