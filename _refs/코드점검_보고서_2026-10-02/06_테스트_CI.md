# 6. 테스트·CI

## F1. 점수 계산 단위 테스트 없음 🟠 {#f1}

`package.json`에 테스트 러너도, 테스트 파일도 없다. 점수 계산은 이 사이트의 핵심인데 B1(누구나 60점)·
B2(규칙 반대) 같은 오류가 화면상으론 그럴듯한 숫자로 나와서 눈으로는 잡기 어렵다. 중고등 로직이 추가되면
더 그렇다.

**제안**:
- `vitest` 추가(설정 거의 없이 TS·`@/` 경로 동작).
- 먼저 `calculateScore`·`calculateTransferEligibility`에 **손으로 만든 `ParsedFile` 객체**로 경계값 테스트:
  - 겹치는 발령 행 → 경력 개월이 중복되지 않는지 (B1)
  - 휴직 구간이 경력·실적에서 빠지는지 (B1, B5)
  - 교과전담 2022.2.28./2022.3.1. 경계, 팀/비팀 4가지 조합 (B2)
  - 2024.2.29. 종료 연수 (B4)
  - 포상 같은 해 2개·3년 3개 → 최상위 1개·최대 2개
- 엑셀 파서 테스트용 파일은 실제 인사기록카드 대신 **가공 xlsx**를 쓸 것(A2).

## F2. CI 범위가 좁고 개인정보 스캔에 빈틈 🟡 {#f2}

**CI**: `.github/workflows/privacy-check.yml` 하나뿐이라 타입 오류·lint 오류·빌드 실패가 그대로 main에 들어갈 수
있다(메인 워크트리는 main 직행 운영이라 더 그렇다). 같은 워크플로에 단계 추가 권장:

```yaml
- uses: actions/setup-node@v4
  with: { node-version: 20, cache: yarn }
- run: yarn install --frozen-lockfile
- run: npx tsc --noEmit
- run: yarn lint
- run: npx vitest run   # F1 도입 후
```

**개인정보 스캔**(`scripts/check-no-network-in-score-calc.mjs`): 목록에 적힌 파일만 한 줄씩 정규식으로 본다.
- 목록 파일이 **import하는 다른 모듈**(예: `settings-container.tsx` → `src/hooks/*`, `src/lib/*`)에 `fetch`가
  새로 생기면 못 잡는다. A1 때문에 지금은 이 스캔이 사실상 유일한 장치라 빈틈이 더 크다.
- 개선안: 목록 파일에서 시작해 `@/` import를 따라가며(간단한 정규식으로 충분) 도달하는 파일을 모두 스캔.
  의도된 예외(설정 페이지의 주소 검색 `/api/geocode` 등)는 허용 목록으로 명시.
- 추가로 A1을 고친 뒤, 배포 응답에 CSP 헤더가 있는지 확인하는 간단한 체크(빌드 후 `routes-manifest.json`의
  `headers`에 `/calculator`가 있는지)를 넣으면 이번 같은 "설정 파일이 조용히 무시되는" 문제를 다시 못 넘어간다.
