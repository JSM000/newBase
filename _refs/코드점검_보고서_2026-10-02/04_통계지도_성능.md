# 4. 통계지도 성능 (`src/components/kakao-map/kakao-map.tsx`, `src/containers/statistics/`)

## D1. 작은 변화에도 마커 전체를 다시 만듦 🟠 {#d1}

**위치**: `kakao-map.tsx:363-520` (마커/클러스터 렌더 effect)

이 effect의 의존성에 `selectedSchoolCode`, `favoriteSet`, `commuteStats`, `schools`가 다 들어 있어서 아래 중
하나만 바뀌어도 **개별 마커 최대 524개를 전부 지우고 새로 만든다** (마커마다 이벤트 리스너 3개씩 다시 등록):

- 학교 하나 클릭(선택 표시만 바뀌면 되는데)
- 즐겨찾기 하트 하나 토글
- 검색창에 한 글자 입력

**수정안**: 역할을 둘로 나눈다.
1. "어떤 학교 마커가 있어야 하나"(schools·viewTier·indicator)가 바뀔 때만 마커를 생성하고,
   `schulCode → marker` Map을 ref에 보관.
2. 선택·즐겨찾기 변화는 별도 effect에서 **해당 마커 1~2개만** `marker.setImage(...)`로 교체.
   (`getMarkerImage`가 이미 캐시를 쓰는지 `marker-image.ts`에서 확인 후 그대로 재사용)

툴팁 내용도 마우스오버 시점에 최신 값을 ref로 읽게 하면 `commuteStats` 변화로 재생성할 필요가 없다.

## D2. 검색어 입력마다 지도 화면 재조정 🟡 {#d2}

**위치**: `kakao-map.tsx:618-630`

`schools`가 바뀔 때마다 `map.setBounds`를 호출한다. 학교명 검색은 한 글자마다 `filtered`가 바뀌므로 타이핑
중에 지도가 계속 확대·이동한다(D1의 마커 재생성도 같이 일어남).

**수정안**: `statistics-container.tsx`에서 검색어에 `useDeferredValue`나 200~300ms 디바운스를 적용해 필터에
넘긴다. 입력창 자체는 즉시 반영되고 지도만 잠깐 늦게 따라온다.

## D3. 기타 🟡

- `statistics-container.tsx:103,106` — `readFreshSettings()`(내부에서 `persist.rehydrate()` 호출)를 lazy 초기값
  두 곳에서 각각 불러 localStorage를 두 번 읽고 재수화도 두 번 한다. 한 번 읽어 둘 다 쓰게 하면 된다.
- `statistics-container.tsx:200-211` 이어붙이기 병합에서 `p.results.find(...)`를 결과마다 돌린다(최대 524²).
  지금 규모에선 체감 없음 — 손볼 일이 생기면 Map으로.
- 지도 범례 색 변경(오늘 작업, `BUCKET_COLORS`)과 관련 — 출퇴근 모드 마커 색 `#e77474`(`kakao-map.tsx:77`)가
  범례 4단계 색과 같다. 출퇴근 탭에선 범례를 숨기므로 지금은 충돌 없음, 나중에 두 모드를 동시에 보여주게 되면
  색을 분리할 것.
