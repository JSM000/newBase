# 5. 번들 크기·코드 정리

## E1. 계산기 페이지에 전국 시군구 경로 데이터가 통째로 들어감 🟠 {#e1}

**위치**: `src/data/maps/korea-sigungu-paths.ts` (491KB), `src/components/sido-detail-map.tsx:4`,
`src/containers/score-calculator/region-select-container.tsx:11`

`SidoDetailMap`은 `SIGUNGU_BY_SIDO[sidoCode]` 하나만 쓰고, 호출하는 곳은 `SIDO_CODE = '33'`(충북) 고정이다.
그런데 전국 17개 시도 경로가 정적 import라 **계산기 지역 선택 페이지 JS에 491KB가 그대로 실린다**.

**수정안 (택1)**:
- 충북만 남긴 별도 파일(`chungbuk-sigungu-paths.ts`)을 만들어 import → 가장 간단.
- 다른 시도 확장 여지를 남기려면 `public/data/`의 JSON으로 빼서 필요한 시도만 fetch
  (통계지도의 `use-chungbuk-boundaries`와 같은 방식).

## E2. 안 쓰는 파일·중복 코드 🟡 {#e2}

**삭제 후보** (import하는 곳 없음):

| 파일 | 크기 | 비고 |
|---|---|---|
| `next.config.mjs` | — | A1 원인. 반드시 삭제 |
| `src/components/korea-map.tsx` | 95줄 | 어디서도 안 씀 |
| `src/data/maps/korea-sido-paths.ts` | 115KB | 위 `korea-map.tsx`만 씀 → 함께 삭제 |
| `src/app/api/route-path/` | — | 410 스텁 (C4) |
| `public/next.svg` | — | create-next-app 기본 파일 |
| `public/data/chungbuk-edu-districts.geojson` | 92KB | 빌드 스크립트가 만들지만 앱에서 안 읽음. 쓸 계획 없으면 생성 자체를 중단 |

**`public/` 안의 큰 로컬 파일**: `public/maps/bnd_all_00_2025_2Q/`(305MB, 행정경계 원본)는 `.gitignore`로
커밋은 안 되지만 `public/` 아래라 `next dev`에선 그대로 서빙되고, CLI로 직접 배포하면 업로드될 수 있다.
빌드 스크립트 입력물이니 `scripts/.data/` 같은 `public/` 밖으로 옮기는 걸 권장. 같은 이유로
`public/data/chungbuk-schools.json`(1.6MB 원본, 앱은 `-render.json`만 사용)도 공개 경로에 둘 필요가 없다 —
`route-ranking.ts`는 `-render.json`을 import하므로 영향 없음.

**중복 코드**:
- `parseDate`·`countMonths`가 `score-calculator.ts`와 `transfer-eligibility.ts`에 똑같이 두 벌 있다.
  B1(구간 병합)을 고치면서 `src/lib/date-utils.ts` 하나로 모으면, 중고등 계산 로직을 추가할 때도 그대로 재사용된다.
- `sleep()`이 `route-ranking.ts`·`kakao-directions.ts`에, `bad()`가 API 라우트 두 곳에 중복 — 사소함.

**설정 파일 자잘한 것**: `.gitignore`의 `public/maps/...`, `*.shp/*.dbf/*.shx`, `.env*` 줄이 중복으로 들어 있음.
