# 2. 주소 검색을 필터바로 이동 + 검색 로직 훅 분리

## 요청 내용

"주소 검색 기능을 사이드바가 아닌 필터 줄로 옮기고, 검색 시에 나타나는 후보 주소들은
사이드바에서 확인하도록 수정" — 입력은 필터바, 결과(후보 목록·순위·경로)는 사이드바로
역할을 나눴다.

## 문제: 상태를 어디에 둘 것인가

기존엔 `commute-panel.tsx`(사이드바) 하나가 주소 입력·검색·후보 선택·길찾기 실행·결과
표시를 전부 들고 있었다. 입력 UI만 필터바로 옮기면 두 컴포넌트가 `address`/`candidates`/
`pickedOrigin` 같은 상태를 공유해야 하는데, 어느 한쪽에만 두면 다른 쪽이 못 읽는다.

## 해결: `use-commute-search.ts` 훅으로 로직 전부 분리 (신규 파일)

집 주소 검색과 관련된 코드(`useGeocodeCandidates`/`useRouteRanking` 호출, 30초 쿨다운,
후보 선택, "나머지도 계산", 에러 메시지)를 전부 이 훅 하나로 옮겼다. `statistics-container.tsx`가
한 번 호출해서 필터바와 사이드바 양쪽에 필요한 조각만 나눠서 props로 내려준다.

```ts
useCommuteSearch({ ready, level, sigungu, ownership, onResult, onSelectCode })
// 반환: address, setAddress, candidates, pickedOrigin, sortDir, setSortDir,
//       cooling, cooldownSec, isSearching, isRanking,
//       geocodeErrorMsg, rankingErrorMsg,
//       searchAddress, useSavedOrigin, pickCandidate, loadMore
```

- **필터바**(`school-filter-bar.tsx`)가 받는 것: `addressValue`/`onAddressChange`/
  `onAddressSubmit`/`addressReady`/`addressSearching`/`addressCooling`/
  `addressCooldownSec`/`onUseSavedHome` — 입력창 + 검색 버튼 + "저장된 집 위치" 버튼만
  그린다. "출퇴근 시간 계산기" 탭에서만 보인다(1번 문서).
- **사이드바**(`commute-panel.tsx`)가 받는 것: `candidates`/`pickedOrigin`/
  `onPickCandidate`/`sortDir`/`onSortDirChange`/`onLoadMore`/`cooling`/`cooldownSec`/
  `isRanking`/`errorMsg` — 후보 목록 표시·선택, 순위 결과, "나머지도 계산"만 담당.
  주소 입력 폼(`<form>`, `<input>`, 쿨다운 카운트다운 등)은 통째로 제거됐다 — 이제
  이 컴포넌트는 약 218줄 중 상당 부분이 줄어든 "결과 표시 전용" 컴포넌트다.

## "저장된 집 위치로 검색" 버튼

예전 대화에서 "지도 들어갈 때 자동으로 길찾기 실행되는 것"을 없애달라는 요청이 있었는데,
그 이후 이번 요청으로 주소 검색 UI가 필터바로 옮겨오면서 이 버튼도 필터바로 같이
이동했다. 여전히 **자동 실행은 없다** — 버튼을 눌러야만(`onUseSavedHome`) 저장된 좌표로
검색이 실행되고 사이드바가 열린다.

## 안내 문구 → 클릭 시 alert 팝업으로 변경

시·군/학교급을 안 고른 상태에선 원래 검색 버튼을 `disabled`로 막고 입력창 아래에
"시·군과 학교급을 먼저 골라주세요"라는 회색 캡션을 항상 표시했는데, 이 줄이 있을 때만
필터 줄 높이가 달라져서 필터 바 정렬이 어긋나 보인다는 지적으로 제거했다.

대신 검색 버튼(`type="submit"`)과 "저장된 집 위치" 버튼을 `addressReady`로 더 이상
비활성화하지 않고, 눌렀을 때(`form onSubmit`/버튼 `onClick`) `addressReady`가 `false`면
`window.alert('시·군과 학교급을 먼저 선택해주세요.')`를 띄우고 `onAddressSubmit`/
`onUseSavedHome` 호출은 막는다. 이 프로젝트엔 별도 toast/dialog 시스템이 없어서(검색
결과 없음) 네이티브 `window.alert`를 그대로 씀.

**추가 수정**: 처음엔 검색 버튼에 `!addressValue.trim()`(주소 입력 전) 조건도 남겨둬서,
주소를 안 쓴 상태에선 여전히 버튼이 흐리게(`disabled`) 보였다. "검색 버튼이 막혀 있으면
왜 막힌 건지 알 수 없다"는 지적으로, 이 조건도 버튼 `disabled`에서 빼고 `onSubmit` 안에서
순서대로 검증하도록 바꿨다 — ①`addressReady` 아니면 시·군/학교급 안내, ②주소가
비어있으면 "집주소를 입력해주세요." 안내. 이제 버튼은 쿨다운/검색 중일 때만 비활성화되고
(이건 버튼 라벨 자체가 "N초"/"검색 중"으로 이유를 보여주므로 alert 불필요), 그 외엔 항상
눌러서 왜 안 되는지 바로 알 수 있다.

## 연동 지점

- `src/containers/statistics/use-commute-search.ts` — 신규, 검색 로직 전체
- `src/containers/statistics/commute-panel.tsx` — 결과 표시 전용으로 축소
- `src/containers/statistics/school-filter-bar.tsx` — 주소 입력 UI 추가, 미준비 시
  `window.alert` 경고
- `src/containers/statistics/statistics-container.tsx` — 훅 호출 + 두 컴포넌트에 props 분배
