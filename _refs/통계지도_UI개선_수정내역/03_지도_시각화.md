# 3. 지도 시각화 (스피너 · 직선거리 표시 · 출퇴근 전용 마커 · 범례 숨김)

## 3-1. 길찾기 계산 중 스피너

"길찾기 API 호출될 때 시간이 꽤 걸리는데 스피너가 보이면 좋겠다"는 요청으로,
`commute-panel.tsx` 결과 영역에 추가:

```tsx
{isRanking && !result && (
  <div className="flex flex-col items-center justify-center gap-3 p-8 text-zinc-500">
    <div className="h-8 w-8 animate-spin rounded-full border-4 border-primary border-t-transparent" />
    <p className="text-sm">소요시간을 계산하는 중입니다…</p>
  </div>
)}
```

`isRanking && !result`(첫 결과가 아직 없을 때)만 스피너로 덮는다 — 이미 일부 결과가 있는
상태에서 "나머지도 계산" 중이면 기존 목록을 가리지 않고, 그 버튼 자체의 "계산 중…"
표시로 충분하다고 판단.

## 3-2. 직선거리만 있는 학교 — 지도에 점선으로 표시

순위 목록에서 아직 실측(도로 경로) 안 된 학교(직선거리만 있음)를 클릭해도 지도에
아무 표시가 없던 문제. `KakaoMap`의 `routeOverlay`에 `selectedPosition` 필드를 추가해서,
`path`가 없으면 집↔학교를 회색 점선(`shortdash`)으로 이어 그린다 — 실제 도로 경로(빨간
실선)와 구분되게.

```ts
// statistics-container.tsx의 routeOverlay useMemo
selectedPosition: hit?.position ?? null,  // path가 있으면 이건 안 씀
```

## 3-3. 출퇴근 탭 전용 마커 스타일 (자료 없음과 구분)

**1차 시도**: 출퇴근 탭에서 "표시·순위 기준"에 따른 마커 색/크기 차이를 없애려고,
`accessor`가 항상 `null`인 `NEUTRAL_INDICATOR` 더미를 만들어 기존 "자료 없음" 렌더링
경로(회색·최소 크기)를 재사용했다.

**문제**: 그러면 "실제로 지표 자료가 없는 학교"와 "출퇴근 탭이라 지표를 안 쓰는 학교"가
똑같이 보여서 구분이 안 됨 — "데이터가 없을 때의 마커와 길찾기에서의 마커를 구분해서
표시하자. 길찾기에서의 마커는 primary색에 크기를 좀 더 키우자"는 요청으로 수정.

**최종**: `NEUTRAL_INDICATOR`는 삭제하고, `KakaoMap`에 `commuteStats` prop(아래 3-4)의
존재 여부로 "출퇴근 모드"를 직접 판단하도록 변경. 출퇴근 모드일 때 마커·클러스터 뱃지
색을 `#e77474`(tailwind `primary`) 고정, 크기는 새 상수 `COMMUTE_MARKER_SCALE = 0.9`
(자료없음 `0.58`보다 눈에 띄게 큼, 지표 "높음" 단계 `1.02`보다는 작게)로 고정.

`marker-image.ts`의 `getMarkerImage`/`createRegionClusterElement`에 `scaleOverride`
매개변수를 추가해서, 지표 구간(`bucket`) 기반 크기 대신 이 값을 그대로 쓸 수 있게 했다
— 마커 그리기 함수 자체의 로직은 안 바꾸고 확장만 함.

```ts
// marker-image.ts
export const COMMUTE_MARKER_SCALE = 0.9;
export function getMarkerImage(maps, color, selected, bucket, scaleOverride?: number) { ... }
export function createRegionClusterElement(name, count, color, bucket, scaleOverride?: number) { ... }
```

```ts
// kakao-map.tsx — 마커/클러스터 렌더 effect
const isCommuteMode = commuteStats !== null;
const color = isCommuteMode ? COMMUTE_MARKER_COLOR : (평소처럼 지표 기반);
image: getMarkerImage(maps, color, isSelected, bucket, isCommuteMode ? COMMUTE_MARKER_SCALE : undefined)
```

경계선(행정구역) 채움색은 안 건드렸다 — `statistics-container.tsx`는 `KakaoMap`에
항상 **실제** `indicator`를 넘기고(더미로 안 바꿈), 마커·클러스터만 `commuteStats`
존재 여부로 자체 오버라이드한다.

## 3-4. 마우스 호버 툴팁 — 출퇴근 탭에선 실측/직선 결과 표시

"호버 툴팁에는 출퇴근 시간 계산에서 나온 결과값을 보여주자. 길찾기 API를 돌리지 못한
학교는 직선거리를, 결과가 나온 학교는 소요시간을 넣자."

`statistics-container.tsx`에서 `commuteResult.results`를 학교코드 기준 `Map`으로 만들어
(`commuteStats`) `KakaoMap`에 전달. `statsView === 'commute'`일 때만 채워지고(사이드바를
아직 안 열었어도, 검색 전이라 빈 Map이어도), 그 외엔 `null`.

```ts
const commuteStats = useMemo(() => {
  if (statsView !== 'commute') return null;
  const map = new Map();
  for (const r of commuteResult?.results ?? []) {
    map.set(r.schulCode, { durationSec: r.durationSec, straightKm: r.straightKm });
  }
  return map;
}, [statsView, commuteResult]);
```

`kakao-map.tsx` 툴팁 내용:

```ts
const detailLine = commuteStats
  ? (commuteStat
      ? (commuteStat.durationSec !== null
          ? `자동차 ${formatDuration(commuteStat.durationSec)}`
          : `직선 ${commuteStat.straightKm}km`)
      : '')  // 아직 이 학교의 결과가 없음(검색 전 등) — 학교명만 표시
  : `${indicator.label} ${formatIndicatorValue(indicator, indicator.accessor(school))}`;  // 기존 동작
```

## 3-5. 범례 숨김

"범례도 숨기자" — `IndicatorLegend`가 지표 기준 색상 범례라 출퇴근 탭에선 의미가 없어서,
`statsView !== 'commute'`일 때만 렌더링하도록 조건 추가.

## 3-6. 탭 전환 시 "학교 개별 마커" 기본값을 탭마다 다르게

클러스터 뱃지는 소요시간/직선거리를 못 보여주므로, 출퇴근 탭에서는 처음부터 개별 마커가
보이는 게 더 유용하다는 요청으로 시작 → 이어서 "순위 보기 탭에서는 반대로 꺼져 있어야
한다"는 요청으로 양방향 대칭으로 마무리됐다.

탭이 바뀌는 그 순간에만(React 문서가 권장하는 "렌더 중 prop 변화 감지 → state 조정" 패턴,
`useEffect`가 아님) `showAllMarkers`를 그 탭의 기본값으로 맞춘다 — 출퇴근 탭은 켜짐,
순위 탭은 꺼짐. 같은 탭에 머무는 동안 사용자가 직접 바꾼 값은 되돌리지 않는다("탭 진입
시 기본값"이지 강제 고정이 아님).

```tsx
const [prevStatsView, setPrevStatsView] = useState(statsView);
if (prevStatsView !== statsView) {
  setPrevStatsView(statsView);
  setShowAllMarkers(statsView === 'commute'); // 출퇴근 탭 진입: true(켜짐) / 순위 탭 복귀: false(꺼짐)
}
```

`useEffect` + `setShowAllMarkers` 조합으로 처음 짰다가, 이 프로젝트에 걸려있는
`react-hooks/set-state-in-effect` 린트 규칙(effect 안에서 직접 setState 호출을 에러로
잡음)에 걸려서, 렌더 중 조정 패턴으로 다시 짰다.

이 로직은 원래 `kakao-map.tsx`에 있었고 비교 기준도 `useRef`(`prevCommuteModeRef`)였는데,
[06_지도컨트롤_필터바로이동.md](06_지도컨트롤_필터바로이동.md)에서 `showAllMarkers` state
자체가 `statistics-container.tsx`로 옮겨가면서 이 로직도 같이 옮겨졌다. 옮기면서 비교
기준도 `useRef` → `useState`로 바꿨다 — 이 프로젝트 lint(`react-hooks/refs`)가 렌더 중
`ref.current` 접근 자체를 막는다는 게 이번에 드러나서(`kakao-map.tsx`에선 왜 안 걸렸는지는
불명 — 아마 예전엔 이 규칙이 없었거나 완화돼 있었을 수 있음), state 비교로 바꿔서 우회.

## 버그: `panelMode` 기준으로 잘못 만들었던 것

3-3~3-5를 처음엔 `panelMode === 'commute'` 기준으로 만들었는데, 1번 문서에서 탭 선택과
사이드바 열림을 분리해둔 상태라 "탭만 누르고 아직 검색 안 한" 상태에선 적용이 안 되는
버그가 있었다(스크린샷으로 확인). `panelMode` → `statsView` 기준으로 전부 고쳤다.
