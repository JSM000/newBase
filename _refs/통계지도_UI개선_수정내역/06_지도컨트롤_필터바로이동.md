# 6. 지도 컨트롤(학교 개별 마커/행정구역 경계)을 필터 바 안으로 이동

## 요청 내용

"학교개별마커, 행정구역경계 설정 버튼도 필터 아래에 넣어서 같이 접었다 폈다 할 수 있게
하자" — [05_필터바_접기.md](05_필터바_접기.md)에서 필터 바를 접었다 폈다 하게 만든 직후,
지도 왼쪽 위에 따로 떠 있던 두 스위치도 같은 필터 바 안에 넣어서 필터 바가 접히면 같이
숨겨지도록 해달라는 요청.

## 문제: `showAllMarkers`/`showBoundaries`는 `KakaoMap` 내부 state였다

이 두 값은 원래 `KakaoMap` 컴포넌트 자체의 `useState`였고, 스위치 UI도 `KakaoMap`이
직접 그렸다(04번 문서). `SchoolFilterBar`는 형제 컴포넌트라 이 state를 못 보고, 스위치를
필터 바 안으로 옮기려면 그릴 곳(필터 바)과 값을 쓰는 곳(지도의 마커/경계선 렌더링)이
분리돼야 한다.

## 해결: state를 `statistics-container.tsx`로 끌어올림 (lift state up)

- `KakaoMap`: `showAllMarkers`/`showBoundaries`를 **읽기 전용 prop**으로 받도록 변경
  (내부 `useState` 제거). 스위치 UI(`Switch` 두 개, 관련 `absolute` 컨테이너)도 통째로 제거.
- `SchoolFilterBar`: `showAllMarkers`/`onShowAllMarkersChange`/`showBoundaries`/
  `onShowBoundariesChange` props를 받아, 기존 필터 줄 아래에 새 줄(`border-t`로 구분)로
  스위치 두 개를 그린다. `04_토글_스위치.md`에서 만든 `Switch` 컴포넌트·라벨 폭(`w-[4.75rem]`)
  스타일은 그대로 재사용.
- `statistics-container.tsx`: `showAllMarkers`/`showBoundaries` state를 여기서 선언해서
  `KakaoMap`(읽기)과 `SchoolFilterBar`(읽기+쓰기) 양쪽에 내려준다.

```tsx
// statistics-container.tsx
const [showAllMarkers, setShowAllMarkers] = useState(false);
const [showBoundaries, setShowBoundaries] = useState(true);

<KakaoMap ... showAllMarkers={showAllMarkers} showBoundaries={showBoundaries} />

<SchoolFilterBar
  ...
  showAllMarkers={showAllMarkers}
  onShowAllMarkersChange={setShowAllMarkers}
  showBoundaries={showBoundaries}
  onShowBoundariesChange={setShowBoundaries}
/>
```

## 딸려온 변경: 탭별 기본값 전환 로직도 같이 이동

[03_지도_시각화.md](03_지도_시각화.md) 3-6에서 만든 "탭이 바뀌면 `showAllMarkers` 기본값을
그 탭에 맞춘다" 로직이 `KakaoMap` 안에서 `isCommuteMode`(= `commuteStats !== null`) 기준으로
동작하고 있었는데, `showAllMarkers` state 자체가 컨테이너로 옮겨갔으니 이 로직도 같이
옮겼다. 컨테이너는 `statsView`를 이미 갖고 있어서, `isCommuteMode`를 거칠 필요 없이
`statsView === 'commute'`로 바로 비교한다.

옮기면서 이전 값 비교 방식도 `useRef` → `useState`로 바꿨다:

```tsx
// 이전(kakao-map.tsx, useRef)
const prevCommuteModeRef = useRef(isCommuteMode);
if (prevCommuteModeRef.current !== isCommuteMode) { ... }

// 이후(statistics-container.tsx, useState)
const [prevStatsView, setPrevStatsView] = useState(statsView);
if (prevStatsView !== statsView) { ... }
```

이유: `statistics-container.tsx`로 옮겨서 처음 lint를 돌려보니 `react-hooks/refs`
(렌더 중 `ref.current` 읽기/쓰기 자체를 에러로 잡는 규칙)에 걸렸다. `kakao-map.tsx`에
있을 땐 안 걸렸던 게 좀 이상하지만(같은 패턴), 어쨌든 지금 규칙 기준으로는 막히므로
React 문서가 예시로 드는 "이전 값을 state로 들고 비교하는" 방식으로 바꿔서 우회했다 —
동작은 동일(탭이 바뀌는 순간에만 한 번 기본값을 맞추고, 같은 탭에 머무는 동안의 사용자
조작은 안 건드림).

## 결과

- 필터 바가 접혀 있으면 두 스위치도 안 보임(필터 바 알약 버튼만 남음).
- 필터 바를 펼치면 탭+필터 줄 아래에 스위치 두 개가 같은 카드 안에 나타남.
- 지도 왼쪽 위에 항상 떠 있던 컨트롤이 없어지고, 그 자리엔 이제 필터 바만 있음(겹침을
  피하려고 위치를 조정하던 5번 문서의 `controlsTopOffset`은 필요 없어져서 삭제).
- (이후 [01_탭_분리.md](01_탭_분리.md) 3차에서) 학교명 검색 입력창도 최종적으로 이 스위치
  줄 오른쪽 끝(`ml-auto`)에 자리 잡았다 — 지도 컨트롤 줄이 "필터와 무관한, 지도 자체를
  다루는 것들" 줄로 자리잡은 셈.
